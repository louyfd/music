0. 一句话
--------------------------------------------------------------------------------
用户看过 V48 之后提了一条："**李萨如图形有三档**"。
V48 第一版把李萨如的三档**折叠**成了上位机上的一个"李萨如"按钮 ——
现在改成 **5 档一一对应**：五个单选按钮、板子在 2->3->4 之间切换也会回报。

--------------------------------------------------------------------------------
1. 本版改了什么
--------------------------------------------------------------------------------
【RTL】
  src\uart_packet_echo.v
    · 新增 localparam `DISP_MAX_MODE = 3'd4`
    · `disp_val` 2 位 -> **3 位**；0xD0 的操作数改成
      `(rx_data > DISP_MAX_MODE) ? DISP_MAX_MODE : rx_data[2:0]`
      （★ 夹紧不是取模：5 -> 4、255 -> 4）
    · `disp_mode_in` 2 位 -> **3 位**
    · `dp_disp_w`/`dp_disp_l`/`dp_disp_r` 全部 2 位 -> 3 位；0x5F 的第 2 个字节
      `{6'd0, dp_disp_r}` -> `{5'd0, dp_disp_r}`
    · ★ `dp_want` 的语义跟着变了：**板子在 2->3->4 之间切换现在也会发 0x5F**
  src\top.v
    · `disp_val` 3 位；写口直接 `disp_mode <= disp_val`（不再补位）
    · ★★ 回报口**删掉了"5 档 -> 3 档"的折叠**：`dsp_rep` 现在就是 `disp_mode` 本身
    · `dsp_rep_lat`/`dsp_rep_d`/`disp_mode_rep` 全部 2 位 -> 3 位
    · ★ 两个方向的"翻转沿 + 数据握手"**一个字没改** —— 5 档有 3 位，
      更需要握手（`3 -> 4` 是 `011 -> 100`，三位全翻）

【上位机（电脑版）】
  fpga_proto.py
    · `DISP_MAX` 2 -> **4**；`DISP_NAMES` 3 项 -> **5 项**：
      ("频谱", "波形", "李萨如·左右", "李萨如·干湿", "李萨如·相位")
    · ★★ **修 `safe_u24` 的搜索窗口**：`range(0, 256)` -> `range(0, 4096)`（见第 4 节）
  fpga_rec.py / spp_assistant.py
    · 0x5F 的 `DISP_MODE` 校验范围自动跟着 `DISP_MIN/MAX` 变成 0~4
    · ★ 界面那行单选是**从 `DISP_NAMES` 自动生成的**，所以 UI 代码【一行都没改】，
      自动变成 5 个按钮（窗口宽度硬约束仍然通过：selftest 里那条 <= 980 还绿着）

【上位机（安卓版）】
  FpgaProto.java / FpgaRec.java / MainActivity.java / activity_main.xml / strings.xml
    · `DISP_MAX=4`、`DISP_NAMES` 5 项（名字和电脑版逐字一致）、5 个单选（11sp 排一行）
    · 顺带把 V48.1 的"回显撞帧头"两处（发送侧消毒 + 接收侧候选帧）同步补齐

【文档】
  tools\协议说明_v2_和弦扩展.md
    · 第 17.2/17.4 改成 5 档；**把"为什么当初想折叠"和"为什么被否"如实写进去了**
    · 版本记录加 v2.10（5 档）/ v2.11（回显撞帧头）

4. ★★ 本版修掉的两个"我自己写错"的地方（如实记录）
--------------------------------------------------------------------------------
① **`safe_u24` 的搜索窗口太小**（V48.1 引入，V48.2 修）
   第一版写的是 `for d in range(0, 256)`，理由看着很合理："时间参数最多挪 255µs"。
   **是错的** —— 帧头是【连成一段】的（0x5A 0x5B 0x5D 0x5E 0x5F），
   当【中间那个字节】落进这一段时，整个 256 的块全是坏的，±255 根本跳不出去：
       v = 0x005E5F（24159µs = 一格 24ms，快曲子真的会用）
         b0=0x5F、b1=0x5E 都是帧头；往下 3 只修好 b0；
         要一直走到 0x006000 才安全 —— 需要 +417，超出 255 窗口。
   ★ 这是**安卓侧的子代理用独立脚本穷举 0~0xFFFFF 抓出来的**：
     ±255 时仍有 **4160 个值不安全**，还包含 tick ≈ 23~24.6ms 那一整段。
   ★ 修法：窗口放到 **4096**（并补了逐字节兜底）。
     为什么 4096 一定够：d 从 0 到 4095 时 b1 至少要进位/借位 16 次，
     而坏值只有连着的那 5 个；b1 一旦变好就保持 256 个值不变，
     那 256 个值里 b0 会取遍 0~255，其中 251 个安全 —— 必定命中。
   ★ 复核：我自己再穷举一遍 0~0xFFFFF —— **零漏网**；
     并且和 Java 侧对拍 131,463 行**逐字节一致**。

② **"3 档折叠"这个设计决定本身就是错的**（V48 引入，V48.2 废掉）
   当初的想法是"李萨如那三档在上位机看来是同一档，粗粒度就没说错"。
   用户一句话就否了：**「李萨如图形有三档」**。
   ★ 教训：**"信息合并"这类决定，只要界面上存在对应物，就该先问用户**，
     不要替用户决定"他不需要区分"。
   ★ 连带教训（也很值钱）：**折叠是"丢信息"，而丢信息的地方往往就是 bug 的温床** ——
     V48.1 那个"回显撞帧头"的 bug 正好发生在这个折叠层附近，
     两件事都说明：**能一一对应就别映射**。

5. 怎么用（用户操作）
--------------------------------------------------------------------------------
· 上位机界面上那行「显示」现在有 **5 个单选**：
    频谱 / 波形 / 李萨如·左右 / 李萨如·干湿 / 李萨如·相位
  点哪个板子就切到哪个（0.35s 防抖后插队发 0xD0）。
· 在板子上按按钮 3 循环，**每按一下**上位机那行小字都会跟着动
  （★ V48.2 起 2/3/4 三档也能分辨出来了；以前那三档不发帧）。
· 打开串口 600ms 后软件自动发 0xCB，板子顺势回报当前档位 —— 一连上就对得上。
· **必须刷本版固件**：老固件（含 V48 第一版）收到 0xD0 03/04 会夹成 2，
  而且 2/3/4 之间切换不回报。上位机不吃亏（显示"未确认"或"未知"），
  但看不到那三档。
