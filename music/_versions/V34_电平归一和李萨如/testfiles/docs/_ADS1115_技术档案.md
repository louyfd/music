## 3. ads1115_ctrl.v 内部结构

### 3.1 时钟节拍与开漏（ads1115_ctrl.v:28-53）

- `div_cnt` 16 位向上计数到 `DIV-1`（=124），到顶那拍 `clk_en<=1'b1` 并清零（:37-39），否则 `clk_en<=0`。
- **整个 I2C 状态机只由 `clk_en` 驱动**：`end else if (clk_en) begin case (state)`（:126-127）。这是一条极其关键的隐含约定（后面 3.6 节会展开）。
- SCL 一个完整周期 = **4 个 clk_en 拍**（四相制），SCL 高 2 拍、低 2 拍，占空比 50%。
- 开漏实现：`scl_low` / `sda_low` 各 1 位，`assign i2c_scl = scl_low ? 1'b0 : 1'bz;`（:51），`assign i2c_sda = sda_low ? 1'b0 : 1'bz;`（:52）。**只有「拉低」和「释放」，没有推高**，符合 I2C 规范。
- 输入采样：`wire sda_in = i2c_sda;`（:53）—— **裸线直采，没有两级同步器**（见第 5.4 节风险）。
- 复位时 `scl_low<=0; sda_low<=0;`（:110-111），即总线释放为高阻，**不会在上电时把总线锁死**。

**时序数值（按实际代码，不按注释）**：
| 量 | 值 |
|----|-----|
| `clk_en` 周期 | 2.5 µs |
| SCL 周期 | 4 × 2.5 µs = **10 µs** |
| SCL 频率 | **100 kHz**（标准模式） |

> ⚠️ **陈旧注释**：ads1115_ctrl.v:26 写「DIV=500 → clk_en 10us → SCL 40us → 25kHz」，与第 28 行的 `DIV = 16'd125` **不符**，`DIV=500` 时的 25kHz 才是那段注释描述的对象。真正正确的换算写在同一文件 ads1115_ctrl.v:319（`clk_en 周期 = DIV × clk = 125 / 50MHz = 2.5us`）。**以 :319 和代码为准。**

### 3.2 配置字的具体数值

高字节是**组合逻辑**按通道算出来的：

```verilog
wire [2:0] ch_mux = (ch == 3'd0) ? 3'b100 :   // ads1115_ctrl.v:96-99
                    (ch == 3'd1) ? 3'b101 :
                    (ch == 3'd2) ? 3'b110 :
                                   3'b111 ;
wire [7:0] cfg_h  = {1'b1, ch_mux, 3'b001, 1'b1};   // ads1115_ctrl.v:101
```

| 字段 | 位 | 值 | 含义 |
|------|-----|-----|------|
| `OS` | bit15 | `1` | 启动单次转换（single-shot start） |
| `MUX[2:0]` | bit14:12 | `100`/`101`/`110`/`111` | **单端** AIN0-GND / AIN1-GND / AIN2-GND / AIN3-GND |
| `PGA[2:0]` | bit11:9 | `001` | **±4.096 V** 量程（1 LSB = 4.096/32768 = **125 µV**） |
| `MODE` | bit8 | `1` | 单次转换模式（power-down 单次） |

合成后的高字节字面值（代码 :93-94 已列出）：

| `ch` | 物理通道 | `cfg_h` |
|------|----------|---------|
| `3'd0` | AIN0 | `8'hC3` |
| `3'd1` | AIN1 | `8'hD3` |
| `3'd2` | AIN2 | `8'hE3` |
| `3'd3` | AIN3 | `8'hF3` |

**写寄存器 = `0x01`（`PTR_CFG`），写完整 16 位配置 = `{cfg_h, CFG_L}` = `{cfg_h, 8'h83}`。**
即：AIN0 → `0xC383`，AIN1 → `0xD383`，AIN2 → `0xE383`，AIN3 → `0xF383`。

写寄存器**每次都是整字重写**（不是只改 MUX 位）。

### 3.3 I2C 状态机全展开

状态变量与用途：

| 变量 | 位宽 | 用途 |
|------|------|------|
| `state` | [4:0] | 主状态（:79） |
| `phase` | [1:0] | 四相子步 0..3（:80） |
| `bit_cnt` | [3:0] | 字节内剩余位数，装载 8（:81） |
| `shifter` | [7:0] | 发送移位寄存器，MSB 先出（:82） |
| `rx_byte` | [7:0] | 接收移位寄存器，MSB 先入（:83） |
| `rd_hi` | [7:0] | 读事务暂存的高字节（:84） |
| `ch` | [2:0] | 当前轮询通道 0~3（:85） |
| `is_read` | 1 | 0=写事务，1=读事务（:86） |
| `ptr_only` | 1 | 1=只写指针不写配置（V 修正的关键，:87） |
| `step` | [1:0] | 写事务步骤 0..3（:88） |
| `byte_cnt` | [1:0] | 读事务 0=读高字节，1=读低字节（:89） |
| `wait_cnt` | [31:0] | 转换等待计数器，**单位是 clk_en 拍**（:90） |

#### 事务总流程（文件头 ads1115_ctrl.v:5-9 的声明，与代码一致）

```
写配置：0x90 → 0x01 → cfg_h → cfg_l → STOP
等 9ms（wait_cnt = 3600 clk_en 拍）
写指针：0x90 → 0x00 → STOP           ← 「读事务前先写指针」这就是标题里的修正
读结果：0x91 → 读高字节(ACK) → 读低字节(NACK) → STOP
切通道: ch = 0 → 1 → 2 → 0
```

#### 逐状态说明

**`S_IDLE`（:132-140）** —— 空闲/发起点
- `scl_low<=0`、`sda_low<=0`（总线释放）、`phase<=0`
- `is_read<=0`、`ptr_only<=0`、`step<=0` —— 每次都**重新发起一次写配置事务**
- 无条件 → `S_START`

**`S_START`（:145-167）** —— 生成 START 条件（SCL 高时 SDA 由高变低）
| phase | 动作 |
|-------|------|
| 0 | `scl_low<=0`（SCL 高）、`sda_low<=0`（SDA 高） |
| 1 | `scl_low<=0`（SCL 高）、`sda_low<=1`（**拉低 SDA = START**） |
| 2 | `scl_low<=1`（SCL 拉低）、`sda_low<=1`；`shifter <= is_read ? ADDR_R : ADDR_W`（`:160`）；`bit_cnt <= 8` → 转 `S_SEND` |
| default | `phase<=0` |

**`S_SEND`（:172-199）** —— 发送 8 位，MSB 先出，四相
| phase | 动作 |
|-------|------|
| 0 | `scl_low<=1`（SCL 低，**此时才允许改数据**）、`sda_low <= ~shifter[7]`（SDA 随 bit7 变化） |
| 1 | `scl_low<=0`（SCL 拉高，从机采样） |
| 2 | `scl_low<=0`（保持高） |
| 3 | `scl_low<=1`（SCL 拉低）；`shifter <= {shifter[6:0], 1'b0}`；`bit_cnt <= bit_cnt-1`；若 `bit_cnt==4'd1` 则 `sda_low<=0`（释放 SDA 给从机 ACK）→ `S_ACK` |

**`S_ACK`（:204-263）** —— 收从机 ACK 并**按事务类型分流**（整个 I2C 的调度中枢）
- phase 0：`scl_low<=1`（SCL 低）、`sda_low<=0`（释放 SDA）
- phase 1：`scl_low<=0`（SCL 高）
- phase 2：`scl_low<=0`（保持高）
- phase 3：`scl_low<=1`；然后：
  - **`is_read==1`** → `bit_cnt<=8`、转 `S_RECV`（:225-226）
  - **`is_read==0`** → `step <= step+1`，再按 `step` 值分支（:229-259）：
    - `step==0`（地址W 的 ACK 完成）：`ptr_only ? shifter<=PTR_CONV(0x00) : shifter<=PTR_CFG(0x01)`，`bit_cnt<=8` → `S_SEND`
    - `step==1`（指针字节完成）：`ptr_only` 则直接 `S_STOP`；否则 `shifter<=cfg_h`，`bit_cnt<=8` → `S_SEND`
    - `step==2`（cfg_h 完成）：`shifter<=CFG_L`，`bit_cnt<=8` → `S_SEND`
    - `step==3`（cfg_l 完成）： → `S_STOP`
    - default → `S_STOP`
- ⚠️ **收到的 ACK 位从未被检查**：`sda_in` 在 `S_ACK` 里根本没被读。从机不响应（NACK）时状态机照样往下走。

**`S_STOP`（:268-310）** —— 生成 STOP（SCL 高时 SDA 由低变高）
| phase | 动作 |
|-------|------|
| 0 | `scl_low<=1`（SCL 低）、`sda_low<=1`（SDA 低） |
| 1 | `scl_low<=0`（SCL 高）、`sda_low<=1`（SDA 低） |
| 2 | `scl_low<=0`（SCL 高）、`sda_low<=0`（**SDA 释放为高 = STOP**） |
| 3 | `scl_low<=1`；然后分流（:289-307）：<br>• `!is_read && ptr_only`：指针写完 → **立即**清 `ptr_only`、置 `is_read<=1`、`byte_cnt<=0`、`scl_low<=0`、`sda_low<=0`、`phase<=0` → 回到 `S_START` 直接开读（**此处不等 9ms**，因为转换早已完成）<br>• `!is_read && !ptr_only`：配置写完 → `wait_cnt<=0`、→ `S_WAIT`<br>• `is_read`：读事务结束 → `S_NEXT_CH` |

**`S_WAIT`（:331-345）** —— 等转换完成，**单位是 clk_en 拍**
- `if (wait_cnt >= 32'd3_600)`：3600 × 2.5 µs = **9.000 ms**
  → 清零，`is_read<=0`、`ptr_only<=1`、`step<=0`、释放总线 → `S_START`（发起「只写指针」事务）
- 否则 `wait_cnt <= wait_cnt + 1'b1`
- 9 ms 的来历（:325-326）：`CFG_L=0x83` → DR=100 → 128 SPS → 转换 7.8 ms，留 9 ms 余量。
- 🔴 **这是全文件最容易改错的地方**：`wait_cnt` 在 `else if (clk_en)` 里递增（:126），所以单位是 **clk_en 拍（2.5 µs）**，不是 50 MHz 周期。代码注释 ads1115_ctrl.v:315-329 专门记录了历史事故：曾经写 `75_000`，实际等于 75000 × 2.5 µs = **187.5 ms**/通道，两通道一轮 377 ms，表现为「摇杆推了没反应」。

**`S_RECV`（:350-375）** —— 接收 8 位，MSB 先入
| phase | 动作 |
|-------|------|
| 0 | `scl_low<=1`（SCL 低）、`sda_low<=0`（释放 SDA 给从机） |
| 1 | `scl_low<=0`（SCL 高） |
| 2 | `scl_low<=0`（SCL 高保持，**在 SCL 高期的第 2 拍采样**）：`rx_byte <= {rx_byte[6:0], sda_in}`（:363）；`bit_cnt <= bit_cnt-1` |
| 3 | `scl_low<=1`；`bit_cnt==0` → `S_SEND_ACK` |

**`S_SEND_ACK`（:380-421）** —— 发 ACK / NACK 并组装数据
| phase | 动作 |
|-------|------|
| 0 | `scl_low<=1`；`byte_cnt==0` → `sda_low<=1`（**ACK，拉低**）；`byte_cnt!=0` → `sda_low<=0`（**NACK，释放**）（:384-387） |
| 1 | `scl_low<=0`（SCL 高） |
| 2 | `scl_low<=0`（保持高） |
| 3 | `scl_low<=1`；`sda_low<=0`（释放）；然后（:403-418）：<br>• `byte_cnt==0` → `rd_hi <= rx_byte`，`byte_cnt<=1`，`bit_cnt<=8` → `S_RECV`（继续读低字节）<br>• `byte_cnt!=0` → 按 `ch` 把 `{rd_hi, rx_byte}` 写入对应输出寄存器：<br>&nbsp;&nbsp;`ch==0 → ain0_data`（:412）<br>&nbsp;&nbsp;`ch==1 → ain1_data`（:413）<br>&nbsp;&nbsp;`ch==2 → ain2_data`（:414）<br>&nbsp;&nbsp;`ch==3 → ain3_data`（:415）<br>→ `S_STOP` |

**`S_NEXT_CH`（:426-441）** —— 通道切换
```verilog
if (ch == 3'd2)  ch <= 3'd0;      // ads1115_ctrl.v:436-439
else             ch <= ch + 1'b1;
state <= S_IDLE;
```
- 代码注释 :427-435 记录了 V19 修正：原来写的是 `if (ch == 3'd1)`，**只轮询 ch 0 和 1**，导致 AIN2/AIN3 从未被采样、接在 A2 上的第二个摇杆完全没反应。现在轮询 **ch 0 / 1 / 2 三个通道，AIN3 不轮询**（省 1/4 时间）。
- 副作用：`ain3_data` 永远是复位值 0。

**default 分支**（:443）：`state <= S_IDLE`。

### 3.4 SDA/SCL 时序生成方式总结

- 时钟由计数器 `div_cnt` + `clk_en` 单拍脉冲产生，状态机**只在 `clk_en` 有效的那一拍推进**（:126）。
- 每个 I2C 位 = 4 个 `clk_en` 拍 = 4 个 `phase`。
- **数据在 SCL 低电平期间改变**（`S_SEND` phase0 / `S_RECV` phase0 释放），**在 SCL 高电平期间采样**（`S_RECV` phase2）。
- 所有总线动作只通过 `scl_low` / `sda_low` 两个寄存器的「拉低/释放」实现，`z` 态交给外部上拉。
- START/STOP 都是标准写法：START = SCL 高时 SDA 下降沿（:152-155）；STOP = SCL 高时 SDA 上升沿（:280-283）。

### 3.5 读回来的 16 位数据如何处理

**结论：不做任何处理。**

- 原始字节 `{rd_hi, rx_byte}` 直接写入 `ain0_data`/`ain1_data`/`ain2_data`/`ain3_data`（:412-415）。
- 因为 MUX 配的是**单端 AINx-GND**（`3'b100`~`3'b111`），量化结果是 **0 ~ +32767 的无符号正数**，不是差分有符号数。
- 端口声明是 `output reg [15:0]`（无 `signed`），所以：
  - ❌ **没有**多位平均
  - ❌ **没有**滑动窗口
  - ❌ **没有**去极值 / 中值滤波
  - ❌ **没有**抖动抑制 / 迟滞
  - ❌ **没有**符号扩展或负数处理
  - ❌ **没有**任何门限、死区、稳定判定
- 也**没有**数据就绪握手信号（如 `data_valid`），下游只能靠「值变了」或定时轮询来感知更新。

## 4. 需求中提到的映射逻辑实际在哪（`top.v`，**不在**上述两个文件）

这一节是为了防止「按档案去改 ads1115_ctrl.v 却找不到代码」。以下全部在 `top.v`。

### 4.1 前提常量（top.v:57-77）

| 名称 | 值 | 说明 |
|------|-----|------|
| `JS_CENTER` | `16'd13200`（top.v:57） | 摇杆居中时的读数 |
| `JS_DEAD` | `16'd1200`（top.v:71） | 中心死区（counts）。V17 从 2600 降到 1200 |
| `JS_TRAVEL` | `16'd12500`（top.v:72） | 从中间推到极端的行程 |
| `JS_STEPS` | `12`（top.v:73） | 每边最多移几个半音 |
| `JS_XSPAN` | `JS_TRAVEL - JS_DEAD` = **11300**（top.v:75） | 有效行程 |
| `JS_XMUL` | `(12*65536 + 11300/2)/11300` = **70**（top.v:76） | Q16 线性映射斜率 |
| `JS_VMUL` | `(255*65536 + 13200)/26400` = **633**（top.v:77） | **V19 后已不再使用**（被查表取代） |
| `JOY_BYPASS` | `1'b0`（top.v:613） | =1 时强制「原调 + 满音量」，忽略摇杆。**当前为 0（摇杆可用）** |

### 4.2 多点平均（top.v:625-682）

- `JS_AVG_LOG2 = 2` → `JS_AVG_N = 4`（top.v:630-631）—— **4 点盒式平均**，V17 从 16 点降下来。
- `JS_TAP_DIV = 16'd32768`（top.v:632）→ 每 655 µs 采一点，4 点窗口 = **2.6 ms**。
- 累加器 `xacc/yacc/zacc` 21 位，取位段 `js_xsum[JS_AVG_LOG2+15 : JS_AVG_LOG2]`（top.v:670-672）完成 `>>2`。
- **没有去极值、没有中值、没有滑窗以外的机制**；注释 top.v:618-623 说明原来的一阶 IIR 因时间常数（0.66 ms）远小于 ADC 更新周期（4.65 ms）而无效，故换成盒式平均。

### 4.3 X 轴 → 移调档位 0~24（12 = 原调）（top.v:694-738）

```verilog
wire signed [16:0] js_xd = $signed({1'b0, js_x}) - $signed({1'b0, JS_CENTER});   // top.v:699 带符号偏移
wire        [15:0] js_xa = js_xd[16] ? (~js_xd[15:0] + 1'b1) : js_xd[15:0];      // top.v:700 取绝对值
wire        [15:0] js_xe = (js_xa > JS_DEAD) ? (js_xa - JS_DEAD) : 16'd0;        // top.v:701 扣死区
wire [31:0] js_xn32 = ((js_xe * JS_XMUL) + 32'd32768) >> 16;                     // top.v:703 四舍五入
wire [4:0]  js_xn   = (js_xn32 > JS_STEPS) ? JS_STEPS[4:0] : js_xn32[4:0];       // top.v:704 钳位到 0~12
```
- 档位计算（top.v:722-737，在 `js_upd` 即每 1024 拍 ≈20.5 µs 一次的快节拍上）：
  - `js_xa <= JS_DEAD` → `trans_cand = 5'd12`（原调）
  - `js_xd[16]`（负偏移）→ `trans_cand = 5'd12 - js_xn`（往低移调）
  - 否则 → `trans_cand = 5'd12 + js_xn`（往高移调）
  - 所以最终范围是 **0 ~ 24，12 = 原调**（`reg [4:0] trans_cand, trans_idx`）。
- **连续稳定判定（这正是需求里的「连续多少个采样一致才提交」）**：`trans_hcnt`（4 位）计数，**必须连续 8 次候选值都相同**才真正提交（top.v:729-736）：
  - `trans_cand == trans_idx` → `trans_hcnt <= 0`
  - `trans_hcnt == 4'd7` → `trans_idx <= trans_cand; trans_hcnt <= 0`
  - 否则 `trans_hcnt <= trans_hcnt + 1`
  - 8 × 20.5 µs ≈ **164 µs** 迟滞，用于压住格子边界上的来回跳档（top.v:706-713 有详细说明）。
- 复位默认 `trans_cand = trans_idx = 5'd12`（top.v:719-720）。

### 4.4 Y 轴 → 总音量 0~255（top.v:740-774）

- 用 **64 项查表** `v_lut[0:63]`（top.v:753-772），索引 `js_y[15:10]`（每档 1024 counts）：
  `wire [7:0] js_vol = v_lut[js_y[15:10]];`（top.v:774）
- 表值：`v_lut[0]=5`、`v_lut[1..25]` 约每档 +10（`v_lut[25]=252`），**`v_lut[26]` 起全部为 `8'd255`**（饱和），即推到约 26×1024 ≈ 26600 counts 后满音量。
- `255` 档实际是 ×255/256，所以推到头不会比以前更早削顶（top.v:741-742）。
- 注释 top.v:745-751 说明：V19 把原来的 `js_y * JS_VMUL(633) >> 16` 换成此表，省掉一个 16×10 乘法器；**要改摇杆音量灵敏度就改这张表**。

### 4.5 AIN2 → 颤音深度（top.v:776-815）

- `js_za = |js_z - JS_CENTER|`（top.v:796-797）
- 索引 `tk = js_za[15:10]`（64 档）（top.v:813）
- **V19 反转为算术式**（原为 64 项表）：`js_tdep = (tk <= 6'd8) ? (8'd200 - tk*21) : 8'd10;`（top.v:814-815）
  - tk=0 → 200（中位最深），tk=8 → 32，tk≥9 → 10（几乎无颤音）。
- 即摇杆**中位颤音最深**，往两边推越来越浅。

### 4.6 跨时钟域与最终消费（top.v:836-884）

- 50 MHz 域把 `trans_idx` / `js_vol` / `js_tdep` 存入 `tr_send` / `vel_send` / `tdep_send`，并翻转 `cdc_tgl`（top.v:841-854）。
- 12.5 MHz 音频域三级同步 `cdc_t1/t2/t3`，**只在检出翻转沿时采样**（top.v:856-880），避免多位总线被采到「高位新、低位旧」的非法组合（top.v:821-834 有详细说明）。
- 复位默认值：`trans=12`、`vel=220`、`tdep=110`（top.v:843-845）。
- 最终：`trans_audio = JOY_BYPASS ? 12 : tr_audio_r` 等（top.v:882-884）。

## 5. uart_tx_ads.v 的结构

### 5.1 波特率与帧节奏分频

| 项 | 值 | 出处 |
|----|-----|------|
| 波特率 | **115200** | uart_tx_ads.v:20 |
| 每 bit 时钟数 | `BAUD_CNT = 50_000_000/115200` = **434** | uart_tx_ads.v:21 |
| 实际波特率 | 50M/434 = 115207.4（**+0.0064%**） | — |
| 帧发送周期 | `tick_cnt` 到 `20'd999_999` → **20 ms** → **50 Hz** | uart_tx_ads.v:32 |
| 一帧时长 | 32 字节 × 10 bit / 115200 = **2.78 ms** | — |

> ⚠️ **陈旧注释**：文件头 uart_tx_ads.v:4 写「**每 1 秒**发一帧」，与代码（20 ms）矛盾。以代码 :23 的注释「20ms @ 50MHz = 1_000_000」和 :32 的 `20'd999_999` 为准。1 秒是旧版本的残留。

### 5.2 发送状态机（uart_tx_ads.v:220-289）

| 状态 | 编码 | 行为 |
|------|------|------|
| `U_IDLE` | `4'd0` | `uart_tx_reg <= 1'b1`（空闲高）。`tx_start` 有效 → `tx_busy<=1`、`tx_idx<=0`、`uart_data <= tx_buf[0]`、`baud_cnt<=0` → `U_START`；否则 `tx_busy<=0`（:235-246） |
| `U_START` | `4'd1` | `uart_tx_reg <= 1'b0`（起始位）。`baud_cnt >= BAUD_CNT-1`（=433）→ 清零、`bit_cnt<=0` → `U_DATA`（:248-256） |
| `U_DATA` | `4'd2` | `uart_tx_reg <= uart_data[bit_cnt]`，**LSB 先出**。每 434 拍推进；`bit_cnt==4'd7` → `U_STOP`，否则 `bit_cnt+1`（:258-268） |
| `U_STOP` | `4'd3` | `uart_tx_reg <= 1'b1`（停止位）。434 拍后：若 `tx_idx >= tx_len-1`（即 31）→ `U_IDLE`、`tx_busy<=0`；否则 `tx_idx+1`、`uart_data <= tx_buf[tx_idx+1]` → `U_START`（:270-284） |
| default | — | `U_IDLE`（:286） |

- 帧格式：**1 起始位 + 8 数据位（LSB first）+ 1 停止位，无校验**。
- `tx_busy` 在 `U_IDLE` 用于反压：`if (tick_flag && !tx_busy)`（:151）。20 ms 周期 vs 2.78 ms 帧长，不会丢帧。
- `tx_start` 是单拍脉冲（:149 先清、:204 再置），所以 `tx_buf` 有整整一拍建立时间，`uart_data <= tx_buf[0]`（:240）读到的是**新值**，不存在竞争。

### 5.3 它发什么格式的数据

**VOFA+ JustFloat 格式**：`7 × float32（小端） + 帧尾 00 00 80 7F`，共 **32 字节**。

`tx_buf` 映射（uart_tx_ads.v:120-131，写入在 :162-201）：

| 字节 | 内容 |
|------|------|
| `[0..3]` | AIN0 float32（小端）← `ain0_data`（压力传感器原始读数） |
| `[4..7]` | AIN1 float32 ← `ain1_data` |
| `[8..11]` | AIN2 float32 ← `ain2_data` |
| `[12..15]` | AIN3 float32 ← `ain3_data` |
| `[16..19]` | 力度值（锁存+平滑后）← `force_data` |
| `[20..23]` | 力度值（换算后、未锁存）← `fraw_data` |
| `[24..27]` | 正在发声的通道数（ADSR 诊断）← `snd_data` |
| `[28..31]` | 帧尾 `00 00 80 7F`（= `0x7F800000` 的小端，即 +Inf，VOFA+ 的 JustFloat 帧尾） |

> ⚠️ 文件头 uart_tx_ads.v:4 写「4 个 float32」也是陈旧的；实际是 **7 路**。注释 :130-131 已说明后三路是 `music_all` 新增的调试通道。

### 5.4 整数 → float32 转换（uart_tx_ads.v:47-118）

- `raw_to_float(raw)`（:47-70）：`tmp = {16'd0, raw}`，然后 `int_to_float(tmp)`。**注意它直接发原始码 `float(raw)`，并没有换算成电压**；代码注释 :51-65 明确说明「要看电压请在 VOFA+ 里用公式换算」，`raw * 125e-6`（1 LSB = 125 µV @ PGA=±4.096 V）只写在注释里。
- `int_to_float(ival)`（:76-118）：
  - `ival == 0` → `32'h0000_0000`
  - 24 级 `if/else if` 优先级编码找最高位 `ival[23]` … `ival[0]` → `exp`
  - `v_shift = ival << (23 - exp)`；`mant = v_shift[22:0]`
  - 结果 `{1'b0, (8'd127 + exp), mant}`
  - 对 **0 ~ 2^24-1** 范围精确。`raw ≤ 32767`（最高位 ≤ bit14）、`force/fraw ≤ 255`、`snd_data` 为通道数，全部安全。**若将来输入 ≥ 2^24，指数会算错**（因为编码器只看 bit23 及以下）。

## 6. 哪些「绝对不能动」，哪些「可以安全修改」

### 6.1 🔴 绝对不能动（改了就坏，代码里有明确警告）

| 项 | 位置 | 原因 |
|----|------|------|
| **写指针 0x00 必须在读事务之前** | ads1115_ctrl.v:5-9、:331-341、:239-242 | 文件标题就是这个修正。去掉「只写指针」事务，读回来的就不是最新转换结果 |
| **`S_WAIT` 的 `wait_cnt` 必须按 `clk_en` 拍计算** | ads1115_ctrl.v:315-329、:332 | 代码明写「★ 以后改这里必须按 clk_en 拍算，不要再按 50MHz 周期算」。历史事故：写成 75_000 → 187.5 ms/通道 |
| **`S_NEXT_CH` 的轮询范围必须是 `ch == 3'd2`** | ads1115_ctrl.v:427-439 | 历史事故：曾写 `ch == 3'd1`，导致 AIN2/AIN3 从未被采样、第二个摇杆完全无反应 |
| **`CFG_L` 与 `wait_cnt` 必须配套** | ads1115_ctrl.v:62-64、:325-326 | `CFG_L=0x83` → 128 SPS → 7.8 ms。若改 DR，`wait_cnt=3600` 必须同步重算，否则读到的是上一次的旧转换值或超时不足 |
| **`ADDR_W`/`ADDR_R` = `0x90`/`0x91`** | ads1115_ctrl.v:58-59 | 对应硬件 ADDR 脚接 GND 的 0x48。只有在改硬件 ADDR 接法时才改 |
| **`cfg_h` 的字段顺序 `{OS, MUX, PGA, MODE}`** | ads1115_ctrl.v:101 | 位序错了就换成别的通道/量程 |
| **四相 `phase` 结构与 `S_SEND` phase0 改数据 / `S_RECV` phase2 采样** | ads1115_ctrl.v:172-199、:350-375 | 违反「SCL 低改数据、SCL 高采样」会破坏 I2C 时序 |
| **`DIV` 与 `S_WAIT` 的时钟域关系** | ads1115_ctrl.v:28、:319 | 改 `DIV` 会同时改变 SCL 频率**和** `wait_cnt` 的实际时长（因为后者以 `clk_en` 为单位）。要改必须两者一起重算 |
| **`top.v` 的 CDC 必须用翻转握手，不能换成普通两级同步器** | top.v:818-834 | 多位总线用普通同步器会采到「高位新/低位旧」的非法组合 → 输出瞬间跳大台阶 → 爆音 |
| **`JOY_BYPASS` 保持 `1'b0`** | top.v:612-613 | 改成 1 会彻底禁用摇杆（只用于无摇杆调试） |
| **摇杆静止偏差大时先改 `JS_CENTER`，不要盲目加 `JS_DEAD`** | top.v:58-71 | 代码明写「★ 如果换摇杆后静止读数偏得多（>1600），先改 JS_CENTER，别再加死区」。V16 加死区到 2600 的后果是「太钝」 |

### 6.3 ⚪ 当前状态的重要事实（避免误判）

1. **`uart_tx_ads` 目前是「死代码」**：`top.v` 里没有任何 `uart_tx_ads` 实例化——搜索全 `src\` 只在 `uart_tx_ads.v` 自身和 `top.v:3100/3102` 的注释里出现。`top.v:3098-3102` 明确写了：
   > 「★ UART 上报（VOFA+）已按要求整体移除：串口引脚 `uart_tx` 已从端口和 `music.cst` 里删掉，引脚空出来了。`uart.v` / `uart_rx.v` / `uart_tx.v` / `uart_tx_ads.v` 这几个文件还留在 `src\` 目录里，但没有被实例化，不参与综合；哪天想恢复上报，重新接上 `uart_tx_ads` 即可。」
2. 因此 `force_data` / `fraw_data` / `snd_data` **在全工程没有任何驱动源**（grep 只在 `uart_tx_ads.v` 内命中）。恢复例化时必须自己接上这三路，否则综合会报未连接/常 0。
3. `top.v:3093-3096` 描述的是**旧版** ADS1115 用途（AIN0/AIN1 摇杆、AIN2 颤音），`uart_tx_ads.v:122` 的注释还写着「AIN0 ← 压力传感器」，两者语义已分叉——**以 `top.v` 的实际连接为准**。
4. `ain3_data` 在本工程永远是 0（AIN3 不轮询，ads1115_ctrl.v:436-439），所以即使恢复上报，第 4 路 float 恒为 0.0。

### 6.4 建议关注的两个设计隐患（现状可工作，但不是最佳实践）

1. **I2C ACK 从不检查**：`S_ACK`（ads1115_ctrl.v:204-263）完全忽略 `sda_in`，从机掉线/NACK 时状态机照常推进，会把总线上的噪声当数据锁存进 `ain*_data`。也没有总线死锁恢复（bus recovery / 9 个 SCL 脉冲复位）。若出现「摇杆读数乱跳/卡死」，可优先怀疑这里。
2. **`sda_in` 无同步器**：`wire sda_in = i2c_sda;`（ads1115_ctrl.v:53）直接采样异步输入。虽然采样点落在 SCL 高电平中段、且 `clk_en` 周期 2.5 µs 远大于亚稳态窗口，风险低，但严格做法是加 2 级同步寄存器。`S_RECV` phase2 是唯一采样点（:363）。
