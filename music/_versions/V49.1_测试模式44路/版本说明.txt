================================================================================
V49.1_测试模式44路 版本说明 —— 测试模式（36 键位 + 8 专门的测试声部 = 44 路同时发声）
                                为什么是 44 路而不是 52 路（有两次布线失败的原文证据）
================================================================================
归档时间：2026-10-12
构建命令：powershell -ExecutionPolicy Bypass -File tools\build_with_cst.ps1 -Mode debug
基线版本：V49_采样率翻倍（本版一行都没动它）

--------------------------------------------------------------------------------
0. 一句话
--------------------------------------------------------------------------------
在 V49（采样率翻倍到 97.656 kHz，吞吐量 3.5156 M 样本/秒）之上加【测试模式】：
按下按钮板第 11 键或上位机发 `0xD2`，**44 路独立振荡器同时发声**
（36 个键位固定在 A2~G#5，另加 8 路专门测试声部排在 A5~E6），
频谱上 44 个峰频域互不重叠、可以一个个数清 —— 对应赛题"现场验证要求：
测试模式下输出多路不同频率音频，频谱可观测对应数量独立谱峰"。

★ 本版的核心取舍：**先要一个"能布通线、能交付"的版本**，而不是纸面上更高的数字。
  最初按 16 路（= 52 路）做，资源被顶到 CLS 90%，**连续两次布线失败**，
  于是降到 8 路（= 44 路）。证据与后续方案见第 3 节。

--------------------------------------------------------------------------------
1. 逐条改动（只在 top.v 的测试模式段内；36 键位路、uart_packet_echo.v、
   lcd_master.v 一个字都没动）
--------------------------------------------------------------------------------
1) `localparam integer T_SLOT_N = 16;` → **8**
2) 时隙选择：`tslot = sample_cnt[6:3]` → **`{1'b0, sample_cnt[6:4]}`**
   （8 个时隙，每隙 **16 拍**）
3) 拍内相位：`case (sample_cnt[2:0])` + `3'd1/3'd2/3'd3`
   → **`case (sample_cnt[3:0])` + `4'd1/4'd2/4'd3`**
   ★★ 这一条必须改：一个时隙宽 16 拍，如果用 `[2:0]` 判据，
      1/2/3 会在同一隙里**触发两次**（cnt=1 与 cnt=9 都满足 `[2:0]==1`），
      ROM 数据会被乘两遍、累加两遍 → 幅度翻倍且状态错乱。
4) `test_freq` 表：只保留 8 项（880/932/988/1047/1109/1175/1245/1319 = A5~E6），
   `default` 给 1319。★ 频带不重叠这条结论仍然成立：键位最高音 **831 Hz** <
   测试音最低音 **880 Hz**（sim 里有一条断言按新参数复算盯着）。
5) AGC 负载常数 **3200 → 1600**（= TEST_ENV 200 × 8 路）。
   ★ 降路时这里必须跟着改：不改就等于替 16 路留负载，44 路会被人为压小声。
6) 段首注释与全文件里"16 路 / 52 路 / 64 拍"的数字全部改成 8 路 / 44 路 / 32 拍，
   并把方案 A 的来龙去脉写在段首（含两次 DesRoute 失败的原文）。

★ 接口（协议侧由另一条线实现，本版只对接，不改它）：
  · 下行 `0xD2`：无操作数、【翻转】语义（和 V48.5 的 `0xD1` 同构，板子为唯一权威）
  · 上行 `0x60`：`[0x60] [TEST_ON]` 两字节，状态变化/复位/`0xCB` 时发一次
  · 板载按钮：**按钮板第 11 键（`btn_new[10]`）**，与 `0xD2` 同权 → 天然双向同步

--------------------------------------------------------------------------------
2. 测试模式的行为（哪些改了、哪些一个字没改）
--------------------------------------------------------------------------------
| 对象 | 测试模式下的行为 | 出处 |
|---|---|---|
| 36 个键位 | 相位累加改用 **`delta[g]`（本键基础音高常数）**，不受移调/八度影响 | `phase[g] <= phase[g] + delta[g]` |
| 36 个键位 | 有效包络 `env_eff[ge] = TEST_ENV(200)`；**ADSR 状态机一个字没动** | `gen_enveff` |
| 36 个键位 | `sounding_mask` 全亮（否则 I2S 以为是静音） | `sounding_mask[ge] = test_on \| (env[ge] != 0)` |
| 音色 | 强制走正弦 ROM（吉他弦的谐波太丰富，频谱上数不清峰） | `src_g = (guitar_on_audio && !test_on) ? ... : rom` |
| 8 路测试声部 | **各自独立的相位累加器 / 频率字 / 包络寄存器**（赛题判据）；波表共享 | `gen_tv` |
| 混音 | 8 路之和 `t_sum` 只加进 **S1（基波）**，S2~S4 不动 | `16'd1: S1 <= sum_env + t_sum;` |
| 采样/时序 | 8 路比键位路**晚一个采样点**（10.24µs）参与混音；`sample_vol` 仍在 cnt=10 锁存 | 段首注释 |

★ 退出测试模式：`env_eff` 逐位回到 `env[g]`、8 路包络按 `trc` 斜坡退回 0、
  相位回到 `inc[g]` 路径 —— 全部是"选择器"而不是"改写状态机"，所以**没有后遗症**。

--------------------------------------------------------------------------------
3. ★★ 为什么是 44 路而不是 52 路（原文证据）★★
--------------------------------------------------------------------------------
按 16 路（= 52 路）做完之后，**连续两次构建都在布线阶段失败**：

    Running routing......
    [60%] Routing Phase 0 completed
    Error: DesRoute failed.
    [70%] Routing Phase 1 completed
    ...
    ERROR (PR0004) : There are total 57 unrouted nets
    RUN_ERR:

失败前的资源实测（`impl\pnr\music.rpt.txt`）：

    Logic  50783/59904 (85%)
    CLS    26768/29952 (90%)     ← ★ 瓶颈
    BSRAM  87/118 (74%)
    DSP    56.5/118 (48%)

★ 这与本工程历史上 V39 那次是**同一类故障**（当时 1340 根未布通），
  根因都是 **CLS 过高 → 布线拥塞**；判据：V49 单独那次 CLS 85% 能布通，
  加到 90% 就布不通 —— 就是这 5% 的差别。
   两次失败的日志分别在 `testfiles\build_v491.log` 与 `build_v491b.log`。

★ 方案 A（本版）：测试声部 16 → **8 路**（省 ~1900 LUT）→ 目标 CLS 回到 ~87%，
  先拿到一个确定可交付的版本。**指标从 52 路降到 44 路**。
★ 方案 B（留待后续单独一轮）：先做 (e) **共享波表** —— 36 份 `sine_rom` 目前是
  **LUT 实现、共 4392 LUT（全片 7.3%）**，共享成 1 张表可省 ~3500 LUT，
  那时不但 16 路塞得下，CLS 还能降到 ~83%，布线从此有余量 —— 再回到 52 路。
  ★ 先 A 后 B 的理由：任何一步失败都始终有一个"能烧、能演示"的位流兜底。

7. 上板验证清单（本版尚未上板）
--------------------------------------------------------------------------------
1) 按按钮板**第 11 键**：应能听到 44 个音同时响（低音区 36 个 + 高音区 8 个），
   再按一下退出；上位机发 `0xD2` 应等效，且上位机能收到 `0x60` 回报；
2) 用频谱仪/示波器 FFT 看音频输出：**低音区能数出 36 个峰、高音区 8 个峰**，
   且两组之间有明显空档（831 Hz 与 880 Hz 之间）；
3) LCD 频谱屏：测试模式下 36 根柱应**等高全亮**（`env_eff = TEST_ENV`，AGC 会整体压）；
4) 退出测试模式后：36 个键位恢复正常演奏、音高/音色/效果与进入前一致（无后遗症）；
5) ★ 顺手复核 V49 的几项（如果还没做过）：音高是否与 V48 一致、吉他音准与衰减、
   混响尾巴长度、波形屏时间基、V44 延迟脉冲宽度 2µs 且两段分得开。

8. 回退
--------------------------------------------------------------------------------
把 `T_SLOT_N` 改回 8 以外任何值都要连带改回时隙/拍内判据与 AGC 负载常数（见第 1 节），
**不要只改一个数**。要完全退回 V49：删掉测试模式段（`gen_tv` / `u_trom` / `t_sum` /
`test_*` 声明与连线）即可，36 键位路本就一行未动。
