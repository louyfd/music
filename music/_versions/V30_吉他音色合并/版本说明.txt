V30 —— 合并「吉他音色 + LCD 电平条」
========================================================================

这一版做了什么
------------------------------------------------------------------------
把 music_player1\music 里做出来的两个功能，搬到我们这条线（V29）上来：

 ① 吉他音色（Karplus-Strong 拨弦物理模型，36 条弦并行）
 ② LCD 频谱的电平条改造（36 位并行改成"一根一根扫描"送）

V29 的【停止键 0xC7/0xC8 + 按键映射 0xC6】一个字没动 —— 两边改的是
完全不同的代码区域，合并后逐行核对过（见下面"怎么确认没搬错"）。

★ 说明：music_player1 那份 top.v 的中文注释被 PowerShell 编码事故毁过
  （一万多个乱码/丢字位置），但【代码是好的】（它 11:26 综合过）。
  所以这次不是"整个文件替换"，而是【按代码骨架重放改动】：
  先把两份文件的注释全部剥掉做逐行比对，拿到 15 个真实差异块，
  再一块一块落到我们的 top.v 上。骨架比对工具和还原脚本见
  D:\CODE\_tmp\{delta_full.py, restore_v2.py, fix_mojibake.py}。

RTL 改动（src/top.v，13 处 + 1 个新模块）
------------------------------------------------------------------------
【音色从两档变三档】
  · reg flute_on  ->  reg [1:0] tone_sel
      0 = 普通（纯正弦）  1 = 笛子  2 = 吉他
      按钮 7（btn_flute）按一下往下循环一格，和原来"按一下换笛子"同一个按钮
  · wire flute_on = (tone_sel == 1);  wire guitar_on = (tone_sel == 2);
      ★ 后面所有"看音色办事"的地方（包络参数、谐波、LED）写法都不用改
  · LED 指示跟着改成三档（tone_sel=0 那一支仍按 timbre_50m 取两支，
    和原来 case({flute_on, timbre_50m}) 的 2'b00/2'b01 逐位相同）

【包络】
  · 新增 ENV_REL_DIV_GTR = 16'd420（释音 ≈2.19s）
    吉他的能量衰减在弦模型里算，所以这里只动释音 —— 抬手后让弦自己响完；
    这个值调小了会把余音一起掐掉。

【弦模型】
  · gtr_s1/gtr_s2：guitar_on 跨到 clk_audio 域（两级同步）
  · guitar_on_d + guitar_start：切到吉他那一拍，把正按着的键也拨一下
  · gen_ks：36 个 ks_string 实例（每个键一份常数化的弦）
      拨弦条件 = key_new[kg]（本键刚按下） | (guitar_start & key_mask[kg])
      ★ key_mask 是【V29 映射之后】的信号，所以按键映射对吉他一样生效
  · gen_unpack 里音源二选一：
      src_g = guitar_on_audio ? ks_smp[g] : rom_dout[g][15:0]
      两个都是 16 位有符号、同量级，所以包络/力度/混响/合唱/延迟全部原样复用
  · harm_sum 在吉他模式下取 0（不再掺 2 次谐波）

【LCD 电平条】
  · 新增扫描口：scan_idx[5:0] / scan_val[7:0] / scan_tgl（约 164 次/秒/键）
      音频域把 36 个键各自的 env[g] 轮流送出去，LCD 收到自己维护 36 项电平表
      -> 每根柱子按【自己那个键】的包络长高，而不是"响=1"的等高柱
  · 删掉 sounding_s1 / sounding_s2 / key_levels（36 位并行那套）
  · u_lcd 例化：.key_levels(key_levels) -> .key_lvl_idx/.key_lvl_val/.key_lvl_tgl

【新模块 ks_string（放在 top.v 文件末尾）】
  · 延迟线 + 两点低通 + 每圈移位阻尼 + 噪声起振，一个采样点用 sample_cnt 的
    0~7 拍算完，剩下 248 拍全闲着
  · 每个键的 NI/FR/DP 三个常数由 tools\ks_model.py 算好（音高偏差 < 1.3 音分），
    按 KEY 常数化 —— 运行时没有查表、没有选择器
  · ★ 为什么并进 top.v 而不是单独一个 .v：Gowin IDE 打开工程时会把文件列表
    锁住，新加的 .v 不被吃进去，重新加载工程报
        ERROR (EX3937) Instantiating unknown module 'ks_string'
    放进 top.v（本来就在列表里）就绕过去了。别再拆出去。
  · 省资源的两个关键（都写在注释里了）：
      dif*FR 一开始写成乘法器，36 份各要一个，实测 DSP 53.5 -> 104.5/118（89%）；
      改成"常数小乘 = 移位相加"后只用几级 ALU（LUT 才 47%，富余）
      每圈阻尼用 (y - (y>>DP))，不占乘法器

怎么确认"没搬错"
------------------------------------------------------------------------
1) 代码骨架逐行比对：合并后的 top.v 和 player1 那份，差异只剩
     · V29 的 key_map 52 行（换掉原来那一行 key_mask = pressed_mask_sync2 | …）
     · V29 的 3 行例化端口 .keymap_we_tgl / .keymap_key / .keymap_note
   别的【一行不差】。lcd_master.v 差异 0 块。
   （脚本：D:\CODE\_tmp\verify_port.py）
2) 综合资源对账：和 player1 那次的差恰好等于 V29 的已知开销（见上）。
3) 回归：
     check_rtl_contract.py        59 项 全过（keymap 常量、协议字节、滑音、包络常数）
     sim_uart_packet_echo.py      45 项 全过（协议行为模型，uart_packet_echo.v 没动）
4) 顺带把 top.v 里【早就存在】的注释乱码修了（46 + 330 行）：
     成因是某个工具按 Latin-1/cp1252 读过 UTF-8 再写回，属于可逆层，
     混着两种编码（cp1252 缺的 5 个位置只有 Latin-1 能解），
     所以反查表要两种编码合起来建；修完 CJK 从 10,415 -> 16,974，
     代码骨架逐行不变（脚本：D:\CODE\_tmp\fix_mojibake.py）。
     ★ 还剩 160 个 '?' —— 那是更早那次事故里字节被吃掉的不可逆位置。

怎么用
------------------------------------------------------------------------
【烧录】_versions\V30_吉他音色合并\bitstream\music.fs
        （要重烧：音色/电平条都在 RTL 里）

【切音色】板子上按【按钮 7】，循环：普通 -> 笛子 -> 吉他 -> 普通
          LED 指示：慢闪/快闪=普通，中速闪=笛子，常亮=吉他
          ★ V29 的按键映射对吉他也生效（拨弦条件用的是映射后的 key_mask）

【已知限制】
 · 吉他不受滑音和移调影响：弦长是每个键的常数，拨弦本来也不该改弦长。
   所以摇杆移调、整帧移调对吉他都没用 —— 吉他永远按琴键自己的音高发声。
 · 录音回传里的"音色"只有 flute_on 这一位（fx_state bit5）：
   录吉他那一段回传回去，上位机还原出来是【普通音色】不是吉他。
   要把吉他也录进去，得改录音协议的效果字节（留给以后，见下面"还没做"）。
