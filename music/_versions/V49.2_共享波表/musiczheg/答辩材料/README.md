# 答辩材料总入口 —— 基于 FPGA 的实时多音色合成电子乐器引擎

> 一句话：**36 路振荡器在片内实时并行合成，零音频采样存储，端到端延迟 ≤ 2 ms（保守；示波器实测按键→出声链路只有 10 µs 量级），三个时钟域时序全部收敛。**

## 1. 这是什么

一台**完全由 FPGA 内部逻辑实时合成声音**的电子乐器，不是音频播放器。

| 项目 | 内容 |
|---|---|
| 赛题 | 全国大学生 FPGA 竞赛 · 选题二（FPGA 电子乐器） |
| 器件 | 高云 **GW5AT-LV60PG484AC1/I0**（GW5AT-60B，Console 60K 开发板） |
| 板卡 | Console 60K + **自画扩展板**（36 键电容触摸 + 36 颗 LED + 双路 I2C + DAC） |
| 工具 | Gowin V1.9.11.03 Education（`gw_sh.exe` 命令行构建） |
| 语言 | **纯 Verilog**（无软核 CPU、无 HLS、无 IP 级音频模块） |
| 代码规模 | **13 个参与综合的 `.v` 文件、11,851 行**（手写 Verilog，不含工具自动生成的 `gowin_pll*`）；`top.v` 单文件 **5,330 行** |
| 迭代版本 | **V29 ~ V48.3，每个版本均有归档**（源码 + 位流 + 版本说明） |

## 2. 强在哪 —— 六个可当场复算的硬指标

| # | 指标 | 数值 | 证据在哪 |
|---|---|---|---|
| 1 | 系统最大吞吐量 | **36 × 97656 ≈ 3.516 M 样本/秒**（V49 采样率翻倍后） | `02_核心指标与合规性说明.md` §1（含逐步算式） |
| 1b | **测试模式同时发声** | **44 路**（36 键位 A2~G#5 + 8 路专门测试声部 A5~E6，`0xD2`/`0x60` + 按钮板第 11 键；频谱上 44 个峰频域不重叠） | `02_核心指标与合规性说明.md` §1.5 |
| 2 | 复音数 | **36**（赛题要求 ≥4，进阶 ≥32） | 同上 §3（振荡器统计口径） |
| 3 | 算法合规性 | **零 PCM 回放**：全系统无任何一段音频采样存储 | 同上 §2（BSRAM 逐块拆解） |
| 4 | 端到端延迟 | **≤ 2 ms（保守说法）**；★ 示波器实测 **T1→T2 ≈ 10 µs**，有摆动（帧相位） | `03_延迟拆解.md`（分段表 + 两个摆动来源与上界 + 测量方法） |
| 5 | 时序收敛 | **3 个时钟域 TNS 全部 = 0.000 / 0 端点**，且**"违例端点数" Setup/Hold 也都是 0** | `02` §5（实测 Fmax 表 + §5.5 那条跨域违例怎么修的） |
| 6 | 资源余量 | Logic 79% / Register 24% / BSRAM 74% / DSP 48% | `02` §4 |

**为什么"3.516 M 样本/秒"是个硬指标**：这 36 路不是分时复用的。每一路都有**自己独立的 32 位相位累加器、自己的波表读口、自己的包络状态机、自己的谐波混合通路**，在**每一个音频采样点上同时**算出一个样本值。详见 §1。

```

   键位映射 (0xC6 可自定义)
        │
        ▼  ② 两级同步器跨到音频域
```

## 5. 时钟树（`music.sdc` + PLL 参数）

```
板上晶振 50 MHz (V22)
   │
   └─► PLLA  (MDIV=14 → VCO 700 MHz)
          ├─ CLKOUT0 ÷ 56 = 12.5 MHz  → clk_audio     音频域（合成/包络/效果/LED 指引）
          └─ CLKOUT1 ÷ 14 = 50.0 MHz  → clk_50m_ext  UART + LCD 域
   │
   └─► clk_50m（原始 50 MHz，直达）  触摸扫描 / 效果寄存器 / 摇杆 / 节拍器

采样率 = 12.5 MHz / FRAME_DIV = 12.5e6 / 128 = 97656 Hz   （FRAME_DIV = 64×1×2）
UART   = 50 MHz / BAUD_DIV 5208 = 9600 8N1（蓝牙模块固定波特率）
```

三个域之间全部用**两级同步器**过渡（或"翻转沿 + 数据握手"），并在 `music.sdc` 里用
`set_clock_groups -asynchronous -group [get_clocks {clk*}]` 声明为异步。

> ★★ **如实说明一处已知问题（V48.3 发现，没有动 SDC）**：
> 上面这句通配 `clk*` **实际只圈到了 `clk_50m` 一个时钟** ——
> PLL 派生时钟的真实名字是
> `u_pll/u_pll_0/PLLA_inst/CLKOUT0.default_gen_clk`（`CLKOUT1` 同理），
> **不以 `clk` 开头**。证据：STA 报告里仍然能查到 `CLKOUT0 -> CLKOUT1`
> 的跨域路径被分析（V48.3 第一次构建正是靠这些路径暴露出 1 个 setup + 6 个 hold
> 违例端点）。
> 也就是说：**跨域那类"假违例"一直是靠"碰巧有正余量"在过关**，
> 而不是靠这句约束排除掉的。
> ★ 我们的处理：**不碰 SDC（项目红线）**，改在 **RTL 侧把跨域链修短**
> （源域先打一拍再跨，见 `02` §5.5）—— 这样既治了根因，
> 也不依赖一句可能失效的约束。要不要真正修 SDC，留给后续版本决定。

## 6. 算法合规性速查（详细论证见 `02` §2）

| 赛题合规要求 | 本设计做法 | 是否存储音频采样 |
|---|---|---|
| 波表合成 | `sine_rom.v`：64×16 四分之一正弦表 + 象限折叠 | ❌ 存的是**单周期波形的一个象限**，不是音频采样 |
| 物理建模 | `gen_ks` → `ks_string` ×36：Karplus-Strong 弦模型 | ❌ 延迟线里是**实时算出来的**振动值 |
| 谐波叠加 | `harm_sum`：1/2/3/4 次谐波（一个采样周期读 3 次表取 4 个谐波） | ❌ |
| **4 种音色** | 普通（纯基波 + 力度给 2 次谐波）/ 笛子（2 次谐波压一半）/ 吉他（KS 物理建模）/ **小号（力度那份之上再垫一层固定的 2 次谐波）** —— ★ 全部是**同一套振荡器换参数**，没有新增任何采样存储 | ❌ |
| 包络 | `gen_env` ×36：每键独立 attack→decay→sustain→release | ❌ 纯状态机 |
| 效果 | 延迟线 `dly_mem` / 混响 `rvb_m1~m3` / 合唱 / 颤音 / Haas | ❌ 存的都是**运行时信号** |

**全系统唯一的两张"表"**：
1. `sine_q[0:63]` —— 0°~90° 的四分之一正弦，**16 位 × 64 项 = 1 Kbit**；
2. `gain_lut[0:511]` —— 声部避让的**增益系数**表（不是波形）。

两者都只描述"波形长什么样 / 增益怎么算"，**不包含任何按时间排列的音频采样**。
这是本设计与"播放 WAV/MP3"的根本区别。
