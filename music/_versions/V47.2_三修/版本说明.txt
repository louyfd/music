1. 修复①：跟谱"按下后同时响起这个音和下个音"
--------------------------------------------------------
用户 2026-10-11 报：跟谱模式下每次按指引按下，会同时响起这个音和下个音，
听感是【同一个音的又一次触发】；★ 只有开了逐音力度才出现。

根因：`gate_snd = gate && ((!wait_mode) || slot_go)` 里那个 slot_go：
    cycle X   用户按对 -> keys_ok_rise -> slot_go <= 1
              这一拍 gate = play_run && (ev_left != 0)   ★ ev_left 还没走完
    cycle X+1 slot_go = 1 且 ev_left != 0
              -> gate_snd = 1  ✗ 谱子把【当前这一格】弹出来了
              -> slot_cur 还是用户刚按的那个音 -> "同一个音的又一次触发"
              （load_now 要 ev_left==0 才能触发，所以它会一直响到本格结束）
★ 为什么开了力度才有：每事件多 2 字节(0xC3 vel) -> 帧更长 -> 用户更容易
  在 ev_left 还没走完时按下，把这个一直存在的隐患暴露出来。

修法：`wire gate_snd = gate && !wait_mode;` —— 跟谱模式下【谱子永不出声】。
★ 这才是跟谱模式的语义：灯亮着告诉你按哪些键，声音来自【你自己按的键】。
★ 而且物理上不可能再漏：只要 wait_mode=1，gate_snd 恒为 0。
★ 正常模式（wait_mode=0）下 gate_snd ≡ gate，和 V46 逐位相同。

2. 修复②：力度从"混音增益"退回到"逐音包络峰值"
--------------------------------------------------------
用户 2026-10-11 报：V47.1 之后"噗声还在"。
根因：V47.1 把力度瞬时乘在【混音总增益】上 —— 那是一条【共用路径】，
      力度一变所有正在响的音（含延音尾巴）都跟着跳 ✗

修法：力度改走【每个音自己的包络峰值】——
    top.v gen_env 里新增：
        wire [7:0] vel_peak_k = (midi_keys_aud[ge] && (midi_vel_aud != 7'd127))
                                ? ({midi_vel_aud, 1'b0} | 8'd1)   // 0->1, 127->255
                                : 8'd255;
    攻击上限从常量 255 换成 vel_peak_k：
        if (env[ge] >= vel_peak_k - ENV_ATTACK_STEP) env[ge] <= vel_peak_k;
★ 无力度（或手弹）时 vel_peak_k ≡ 255 -> 两句逐字等于原代码，逻辑逐位相同。
★ 力度缩放的是【这个音自己的包络峰值】—— 起音就从正确音量开始，
  【没有任何增益跳变】，所以不会有"噗"；且完全不碰混音总增益，
  正在延音的音一个比特都不动。
★ 不需要任何新存储器：midi_keys_aud 在整个音期间为 1、midi_vel_aud 在整个
  事件期间不变，所以这是纯组合逻辑。
★ V47.1 那段 mix_scale_v 已整段撤掉，恢复成 V46 的 `mix_scale_f = mix_scale`。

3. 修复③：LCD 刷屏看门狗（卡死自愈）
--------------------------------------------------------
用户 2026-10-11 报：LCD 有时卡死定住不动；★【同时连续按下多个琴键】就会出现；
卡死时【蓝牙/UART 还能用】-> clk_50m_ext 域是活的 -> 是状态机卡住了。

lcd_master.v 新增（纯附加）：
    localparam [25:0] LCD_WD_LIMIT = 26'd40000000;   // 0.8s @ 50MHz
    state 连续 LCD_WD_LIMIT 拍没变化 -> lcd_wd_ovf -> 强制回 S_POWER_ON
    主状态机里作为【最高优先级】分支，排在 case(state) 之前。
★ 正常刷屏时状态推进频繁、计数器一直被清零，【一次都不会触发】。
★ 回 S_POWER_ON（不是直接 S_INIT）—— 连 PWR_DELAY 一起重走，对模组更稳妥。
★ 阈值 0.8s 是留足余量的选值（本文件里最长的合法等待是 sec_cnt 的 ~250ms）。

6. 下一版 V48（用户已确认"归到 V48 一次修好"）
--------------------------------------------------------
① LCD 显示切换接上位机 + 双向同步
     下行 0xD0 + 1 字节 disp_mode（0=频谱 1=波形 2=李萨如）
     上行 0x5F + 2 字节 disp_mode, rec_on   ← 全新帧，不动 0x5D
     ★ 板子按 TTP 键3/键10 时也要回报，这样 PC 上的控件会跟着变。
     用户要求："所有 TTP 上的可调按键全部在上位机上也可调 + 状态同步"。
     已核对：16 个键里 9 个功能【已经】有上位机控制，真正的缺口只有
     显示模式（键3）和录音状态回报（键10）。
② 频谱切到李萨如再切回来【变空白】的修复
     根因：lcd_master.v 的 bar_state[] 是"每列上次画完的高度"缓存，
     bar_dirty = (bar_state[col] != tgt) 决定要不要重画；
     切模式时 S_CLEAR_BAR 清了屏但【没清 bar_state】-> 切回来时
     每列高度和缓存一样 -> bar_dirty=0 -> 一根都不重画 -> 空白。
     修法：切模式时置 bar_force，让 bar_dirty 强制为 1，
     约 0.35s 后清掉（一帧远小于这个时间）。bar_force=0 时表达式逐字等于原样。
③ 上位机/安卓侧由子代理实施（已派出）。
