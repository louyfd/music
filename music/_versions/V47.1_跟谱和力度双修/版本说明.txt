1. bug①：跟谱模式"没锁住第一个音"（用户 2026-10-11 报）
--------------------------------------------------------
症状：跟谱模式下传完谱【响一声就停】，本来该停在第 1 格等用户按，
      却自己把这一格弹了出来。★ 每一格装载后都会这样，不只第一格。

根因：need_mask 比 rd_slot 【慢一拍】。
    cycle N   装载：rd_slot <- 0、ev_left <- dur、slot_go <- 0   ✓ 这拍是对的
              （need_mask 也在这一拍采到的是【哨兵时期】的 slot_cur = 0）
    cycle N+1 rd_slot 已经是 0，但 need_mask 还是上一拍采的 0
              -> need_none = 1  ★假报"这是休止格"★
              -> slot_go 被那个 else if 置回 1
    cycle N+2 need_mask 才更新，need_none 变 0 —— 已经晚了
  于是 gate_snd = gate && slot_go 被这假的一拍绕过去，这一格就发声了。
  ★ 而且 slot_go 是 else if 链、置 1 后会一直保持到下次装载 ——
    所以 ev_left 走完后还会【不等人就往下载载】，跟谱模式形同虚设。

修法：load_now 打一拍（load_now_d），把【装载后那一拍】的 need_none 屏蔽掉。
      wire need_none_ok = need_none && !load_now_d;

★★ 会不会影响播放连贯？（用户专门问了，已用仿真证明）
  · 正常模式（wait_mode=0）：slot_go 那个 if 链的【第一条】就是
      else if (!wait_mode) slot_go <= 1'b1;
    优先级最高，need_none_ok 那条【根本轮不到被判断】。
    → 仿真断言：修复前后每一拍 (slot_go, gate_snd, load_now) 【完全一致】✓
      装载间隔恒等于 DUR+1，没有多插拍 ✓
  · 跟谱模式：因为 need_mask 下一拍就更新，屏蔽最多让"推进"晚
    【1 个 clk = 20ns】。而跟谱一格是 tick_us 级（几百 µs ~ 几十 ms），
    20ns 在时间轴上完全不可见 ✓
  · 休止格照旧自动放行 ✓

★ 顺带澄清一个容易搞错的语义（已写成断言钉住）：
  跟谱模式下【谱子本来就不该出声】—— 灯亮着告诉你按哪些键，
  声音来自你自己按下去的键。所以"全程 gate_snd=0"是【设计如此】，
  不是故障。真正要验的是"按对之后能推进"。

2. bug②：加了力度以后每个音都"噗"一下（用户 2026-10-11 报）
--------------------------------------------------------
根因：V38 用 mix_scale_r 【斜坡】治"起音噗声"，那条斜坡是为
      "声部数变化"设计的（SCALE_STEP=1/采样点，落差 96 步 ≈ 2ms）。
      V47 把力度接到了【同一个斜坡目标】上，于是每个音起音那一瞬：
        n_voice +1 且 力度从 127 掉到本音力度
        -> scale_tgt 猛掉（比如 256→160）
        -> 但斜坡要 2ms 才走完
        -> 【这 2ms 里起音是按旧的大音量出来的】，然后再缩下去
        -> 每音一声"噗"
      ★ 是"把力度塞进斜坡目标"这件事本身错了，不是力度错。

修法：把力度从斜坡目标里【拿出去】——
      · scale_tgt 恢复成只跟声部数（= V46 逐位相同，V38 治噗声原样保留）
      · 力度改成乘在斜坡【之后】瞬时生效：
          mix_scale_f = vel_bypass ? mix_scale
                                   : ((mix_scale * vel_gain) >> 7)
      · vel = 127（满幅）完全旁路，mix_scale_f 逐位等于 mix_scale。

★ 代价（已在版本说明里如实告知用户）：力度瞬时变化时，正在延音的那些音
  也会跟着跳一下。这和 V38 那个"每个音都噗"不是一回事（V38 是每次加音
  都掉一档；这里只在力度真的变了时跳，且被新音起音盖住）。
  ★ 如果试听还能听出来，就得改成【逐音力度】（每个音自己的增益，
    要动发声路径，改动大得多）。

5. 下一版（V47.2）要做：LCD 卡死自愈

★ 用户的猜测对得上：如果某个 phase 的推进条件依赖【实时数据】，
  连续弹多个音时数据一直在变，条件就可能被错过 -> 卡死。
