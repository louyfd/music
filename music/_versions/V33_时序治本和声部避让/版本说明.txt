V33 —— LCD 时序治本 + 大跳不再撞声部（+ 省出 36 个 DSP）
========================================================================

一、LCD 那条时序路径治本了（这次是用户点名要做的）
------------------------------------------------------------------------
【问题】CLKOUT1(clk_50m_ext) 上一直有 setup 违例，最差 -3.065ns：
        u_lcd/wave_peak -> 15 级优先编码器 -> 16 位桶形移位 -> cur_data
        全挤在一个 50MHz 周期里（实测数据延迟 22.5ns > 周期 20ns）。
        V26/V27 就有名，V31 -1.1ns，V32 涨到 -3.1ns。

【做法】把"峰值 -> 移位量"打一拍：
        wave_peak -> peak_msb -> **peak_msb_r(新加的寄存器)** -> wave_sh -> ...
        峰值是"快攻 + 84ms 慢放"的慢信号，移位量跟着它走，
        插这一级只是让缩放比峰值晚 20ns 生效 —— 显示上完全看不出来，
        但把最长的那条组合路径从中间切断了。
        改的是 lcd_master.v，**没碰任何音频链路**。

【结果】最差 slack：-3.065ns -> **-0.162ns（只剩 1 条）**。
        ★ 说实话：没有做到严格的 0 违例。剩下这条 0.16ns 是"刚刚差一点点"，
          且仍然在 u_lcd 里（显示通路，音频域一条都没有）。
          V33 加了"滑音八度守卫"（见下）又往音频域塞了几十个比较器，
          布局一挪这条路径又紧了 0.16ns —— 属于同域布局的抖动。
          真要彻底归零，得再给 u_lcd 那条路加一级流水（下一版做）。

二、大跳被截断 / 丢音 —— 根因不是"来不及"，是【撞到同一个声部】
------------------------------------------------------------------------
【现象】放谱子时音程跳得大，会出现截断、甚至像丢音。

【根因】★ 不是板子响应不过来（声部切换只要 2.9µs，一帧 20ms 起，
        时间上绰绰有余）。真正原因是【36 个声部会被两个音抢】：
          同一个音名，用不同的八度偏移会落在【不同的键】上。例如 C6：
             o=+1 -> 键25（发 C6）      o=+2 -> 键13（60+24 = 84，也发 C6）
          而一个声部同时只能有一个音 —— 后一个音一按下去，前一个音的
          余音就被掐掉了（听感 = 截断；短音甚至像"丢了"）。
        大跳时正好最容易发生：C5(o=0,键25) -> C6 如果也选键25，就撞上了。

【修法】上位机挑八度偏移的判据从"只看折返数"改成三级：
          ① 折返音最少
          ② 【不撞上一个事件正在响的那些键】（新增，专治这个毛病）
          ③ 尽量和上一个事件用同一个偏移（少来回换 = 少撞车）
          ④ |o| 最小、优先 0（保证音域内的老谱子逐字节不变）
        于是 C5 -> C6 现在选 键13 + o=+2（发声音高仍是 C6），
        **换了一个空闲声部**，前一个音的余音不会被掐。
        （实测：C5->C6 = 键[25]oct+0 / 键[13]oct+2，发声音高 72 / 84 ✔）

【还有一个真正的硬上限】同一格里【同时按下】的音，如果跨度超过 3 个八度
        （比如 C2 + C6），36 个声部怎么摆都放不下 —— 仍会折返（报告里会写明
        几个音）。要根治只能加声部：实测每条声部约 240 LUT + 1 BSRAM + 1 DSP，
        而这一版刚腾出 36 个 DSP（见下），加 12~24 路是可行的，等你要了再做。

三、顺带：滑音 × 八度偏移的 BUG 修了
------------------------------------------------------------------------
【问题】last_delta 记的是"上一个音在它自己那个八度域里"的频率字；下一个音
        可能被事件八度偏移挪到别处。两者八度不同还硬起滑的话，发声会从
        "上一个音被移了八度"的位置开始爬 —— 听感就是大跳时音头跑到别的八度。
【修法】gen_phase 里起滑条件加一条 `voice_oct[g] == oct_s2`：
        八度变了就【直接就位、不起滑】。
        ★ 八度相同时（手弹、以及绝大多数同格偏移一样的情况）行为与以前
          【逐位相同】—— 原来的滑音效果一个字没变。

四、省资源（给以后的古筝/鼓腾地方）
------------------------------------------------------------------------
起振噪声幅度原来是每条弦一个乘法器：nz * vel[7:4]。
vel 只有 4 位 = 4 个移位相加就等价（枚举全部 4096 组 (nz, vel) 验证**逐位相同**，
极值 30720 不溢出）。改完：
    DSP       71.5/118 (61%)  ->  **53.5/118 (46%)**   （MULT12X12: 43 -> 7）
    Logic     32219           ->  36408  (61%)          （换来的是 LUT）
    Register  13098           ->  13098  （不变）
    BSRAM     71/118          ->  71/118 （不变）
于是：
    · 古筝 21 弦（同款 KS 引擎）≈ +5k LUT +21 BSRAM +21 DSP  -> 放得下
    · 鼓（模态，时间复用）≈ +3k LUT +8 DSP                    -> 放得下
    · 仍建议鼓走采样（最省最真），古筝走物理建模
★ 原来的音效一个都没动：噪声幅度逐位等价、滑音/延音/颤音/延迟/混响/合唱
  的代码路径一个字未改（delay/chorus/reverb/tremolo 的常数与调用点全原样）。
