1. 本次做了什么
--------------------------------------------------------
工程现在有【两份并列】的引脚约束，同一时刻只能启用一份：

    src\music.cst          调试版（原来的，一个字节没动）
    src\music_release.cst  实装版（交付用）★ 本次新增

两者差别【只有 8 个引脚】（实装 PCB 的走线）：

    信号        调试版      实装版     说明
    --------    ---------   ---------  ------------------------------
    uart_txd    W22    ->   V18        蓝牙是【开发板这头】的 TX/RX
    uart_rxd    W21    ->   G21
    scl         C22    ->   B22        琴键1 = 键 0~11 （RTL kp1）
    sdo         F18    ->   E18
    scl2        E21    ->   C22        琴键2 = 键 12~23（RTL kp2）
    sdo2        E22    ->   F18
    scl3        B22    ->   E21        琴键3 = 键 24~35（RTL kp3）
    sdo3        E18    ->   E22

★ 琴键那三组是【整个轮换了一圈】的（1<-3、2<-1、3<-2），
  因为实装 PCB 的走线就是这么布的。
★ 信号名和 RTL 的对应关系【没变】：scl/sdo=kp1=键0~11，依此类推。
★ 没被提到的引脚【一律保持调试版原样】，包括 led(U12/READY)、
  led_glide(G11/DONE)、lat_key(C19)、lat_pcm(C18)、
  led_scl(V17)、led_sda(W17)……
  → 所以 build_console.tcl 里那三行
      set_option -use_done_as_gpio / -use_ready_as_gpio / -use_cpu_as_gpio
    【不用改】，实装版照样写 1。

2. 怎么在两份之间切换（★ 别手改 music.gprj）
--------------------------------------------------------
    pwsh -File tools\build_with_cst.ps1 -Mode release   # 实装版
    pwsh -File tools\build_with_cst.ps1 -Mode debug     # 调试版

脚本做三件事：
    ① 改 music.gprj 里那两个 type="file.cst" 的 enable 标志
       （用 .NET 写回，不带 BOM，其余字节原样保留）
    ② 严格复核【恰好启用一份】
    ③ ★ 构建后硬核对 impl\pnr\music.fs 的时间戳【必须变新】——
       这是坑 29（构建脚本编了另一个工程却照样报 RUN_OK）的判据。
       不通过就以非 0 退出，不会让你拿到一个"看着成功其实没编"的结果。

music.gprj 里现在是：
    <File path="src/music.cst"          type="file.cst" enable="0"/>
    <File path="src/music_release.cst"  type="file.cst" enable="1"/>
（★ 归档时的状态 = 实装版生效。要回到调试版就跑 -Mode debug。）

★ 已实测确认：Gowin【接受】两份 cst 只启用一份这个机制 ——
  本次构建就是在这个状态下跑完的，合成/PnR 全程没有相关报错。

4. 本次顺手记下的两个坑（详见工作交接.md 第 5 节 30 / 31）
--------------------------------------------------------
坑 30：本机是 PowerShell **5.1**，读 .ps1 按 ANSI(cp1252) 解码 ——
       脚本里写中文【必须存成 UTF-8 带 BOM】，否则报一堆莫名其妙的
       `Unexpected token` / `Missing closing '}'`，而且报错里中文是乱码。
       ★★ 并且 `edit`/`write` 工具改文件会【去掉 BOM】——
          每次用工具改完 .ps1 都要重新补 BOM 再跑。
       判据：前 3 字节应当是 EF BB BF。

坑 31：`uart_packet_echo.v` 里 `wait_mode` 声明了两次
       （端口列表 `output reg wait_mode,` + 体内 `reg wait_mode;`），
       构建报一条 `EX3628 Redeclaration of ANSI port`。
       ★ 这是 **V43 就有的**（V43 归档第 527 行同样如此），V45 构建日志里
         也有同一条 —— 不是本次引入的，类型位宽一致，综合结果不受影响。
       ★ 别顺手去删体内那行：任何 RTL 改动都要重新构建并重核时序
         （clk_50m 余量现在只有 ~1.5%），不值得为一个警告付这个代价。

5. 只有板子能验的（本次归档时未上板）
--------------------------------------------------------
1. ★ 最重要：实装板接上后，**三组琴键弹出来的音对不对** ——
   琴键1（B22/E18）应当弹【最低的 12 个音】，
   琴键2（C22/F18）中间 12 个，琴键3（E21/E22）最高 12 个。
   如果发现整组错位（比如最左边那组弹出高音），说明琴键编号和
   RTL 的 kp1/kp2/kp3 对不上，要回来改 music_release.cst 里那 6 行。
2. 蓝牙能不能通（V18/G21）。★ 如果完全不通，第一个要怀疑的就是
   TX/RX 接反 —— 把 music_release.cst 里 uart_txd / uart_rxd 两行对调，
   跑 -Mode release 重新构建即可。
3. 其余全部照旧验一遍：LCD、I2S 出声、摇杆、按钮板、
   36 颗 LED 指引、录音/播放、跟谱模式、节拍器。
