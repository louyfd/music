V38 —— 修两个实机 bug：起音时的"噗"声 + 蓝牙发送误翻转效果开关
========================================================================

一、这一版做了什么
------------------------------------------------------------------------
用户逐版烧录试听后报了两个问题，这一版把它们都修掉了：

  A. 【每个音起音时有一声"噗"】—— 用户确认"从 V34 开始有"。
     根因：V34 引入的 `voice_scale(n_voice)` 是按【整数声部数】查表的、
     7 档硬台阶。每起音一个音，系数就整档跳一次（N=1→2 是 256→192，
     所有在响的音同时掉 25%），一个采样点内完成 —— 那就是"噗"。

  B. 【播放时滑音/延音会自己打开，谐波自己关掉】—— 多个开关一起变。
     根因是两层叠加：
       ① 上位机把效果命令【插队】发出去（PC 的 `_send_front` / 安卓的
          `priorityQueue`），而谱子是分批发的，命令正好插在两批【中间】——
          那个位置就是帧的内部。板子收到 0xC9/0xCA 会把紧跟的一个字节
          当成操作数吃掉，于是整帧从那里开始字节边界全错，而效果开关
          已经被翻转了。
       ② `uart_rx.v` 每一位只在位中点采【一次】，线上一个毛刺就能让
          字节错位；错位后的数据被当成命令字读出任意值（包括 0xC9）。
          而 0xC9 这类命令是不受开窗限制的，直接就翻转了开关。

  ★ 合成链路、PLL、music.cst、music.sdc、sine_rom、I2S 帧参数、
    协议字节语义【一个都没动】。

二、问题 A 的修法：给缩放系数加斜坡（top.v）
------------------------------------------------------------------------
原来是：

    wire [8:0] mix_scale = voice_scale(n_voice);        // 组合查表，硬跳
    wire signed [32:0] mix_mul = mix_pre * $signed({1'b0, mix_scale});

现在改成：

    wire [8:0] scale_tgt = voice_scale(n_voice);        // 目标值不变，档位表一个字没改
    reg  [8:0] mix_scale_r;
    always @(posedge clk_audio) begin
        if (rst_audio_sync) mix_scale_r <= 9'd256;      // = N=1，等价于原来的 >>>1
        else if (sample_en) begin
            ... 每采样点向 scale_tgt 走 1（到位就直接取目标值）...
        end
    end
    wire [8:0] mix_scale = mix_scale_r;

  · 最坏一档（256→90）走 166 个采样点 ≈ 3.4ms。人耳对 3ms 的电平变化无感，
    台阶却没了 —— "噗"声消失。
  · ★★ 档位表 `voice_scale()` 【一个字都没改】，只是不再一步到位。
  · ★★ `mix_scale_r` 是寄存输出，但 `mix` 仍然用它做【组合】乘法 ——
    没有额外打拍，整条链路的时序与 V34~V37 完全一致。
  · ★★ N=1（单音、以及所有只有一个声部在响的曲子）时 scale_tgt 恒为 256，
    而复位值也是 256 → mix_scale_r 一直不动，取到的值与改之前【逐位相同】。
    斜坡只在"声部数真的变了"的时候才动。

三、问题 B 的修法之一：接收端抗噪（uart_rx.v）
------------------------------------------------------------------------
改了两处：

  ① **每一位采 3 次、3 取 2 表决**
       采样点：baud/2 - baud/8 、 baud/2 、 baud/2 + baud/8
               (5208 时 = 1953 / 2604 / 3255，离位边界 0 与 5208 都很远)
       移入点：baud/2 + baud/8 + 1 （见下面的"踩到的坑"）
     单个毛刺打不掉这一位。

  ② **起始位中点复检**
     原来 `!rx_i && !recv_start` 只要见到一次低电平就启动接收 ——
     线上任何一次窄毛刺都会被当成起始位，随后整帧错位。
     现在到起始位中点再看一眼：还是高电平就立刻作废这一轮。

  ★★ 正常数据下三次采到的值相同，表决结果 = 原来那一次的值
     → 【正常通信逐位不变】，只有噪声情况下才不同（那正是要修的）。

  ★★ 踩到的坑（第一次实现就是错的，被仿真抓住了）★★
     Verilog 的 `<=` 是【下一拍】才成立。第一版把移入写成
         if(bps_cnt == samp_c) samp_v[2] <= rx_i;      // 下一拍生效
         if(bps_cnt == samp_c) recv_reg <= {maj(samp_v), ...};   // 同一拍就读 -> 旧值
     结果第三次采样用的是【上一位】的旧值，比原来的单点采样还糟。
     修法：移入点改成 samp_c + 1（这时三次采样都已站住）。
     `testfiles\sim_uart_rx.py` 的 [1] 节专门钉住"samp_d = samp_c + 1"这一条。

四、问题 B 的修法之二：插队不再打断帧（上位机）
------------------------------------------------------------------------
**电脑版（spp_assistant.py）**：`_send_front` 原来无条件
`self.txq.queue.appendleft(...)`。现在：

    with self.txq.mutex:
        if self.txq.queue or self._tx_busy:
            return False            # 还有没发完的 -> 让调用方走 put()（排队）
        self.txq.queue.appendleft((payload, label))

  · 新增 `_tx_busy`（写线程正在写一项时置位）—— 因为写线程是
    "取出一项 → 整项阻塞写完"，队列空并不等于没在发。
  · ★ 空闲时（用户没在发谱子）队列是空的，行为和以前完全一样：
    按下就发。"点开关有延迟"的体验一点没丢。

**安卓版（BtSpp.java）**：改成"谱子发完了才轮到控制命令"：

    byte[] d = null;
    if (txQueue.isEmpty()) {        // ★ V38：普通队列里还有谱子就先发谱子
        d = priorityQueue.poll();
    }
    if (d == null) {
        d = txQueue.poll();
    }

  · 命令仍然进 `priorityQueue`（`enqueue` 一个字没改），只是**取得晚**。
    这样命令永远落在整批之后，不会插进帧内部。
  · ★ 附带好处：`dropPending()`（"停止演奏"清谱子字节）天然只清普通队列，
    用户刚点的效果命令不会被一起丢掉 —— 这条原有的测试不用改就继续通过。

**板内再加一道门（uart_packet_echo.v）**：开窗接收谱子期间
（`armed == 1`）**直接忽略** `0xC9` / `0xCA`。
  · 这两条命令有操作数、会吃掉谱子的字节，正是帧被破坏的入口。
  · 开窗期间收到就当作未知字节丢弃（帧不破、命令不生效）；
    上位机现在也会等到帧发完再发，所以功能一点不少。
  · ★ 只挡这两个。`0xCC`（八度偏移）是**帧内合法命令**，绝对不能挡；
    `0xC6/0xC7/0xC8/0xCB` 没有操作数、不会吃字节，行为保持原样。

**再补一层超时（uart_packet_echo.v）**：`fx_left` / `tone_left` 这两个
"等操作数"状态加了 3 个字节时间（3 × 5208 拍）的超时 —— 万一操作数丢了，
它们不会一直挂着、把后面任意一个字节当成操作数吃掉。

七、上板子看什么 / 没验到的
------------------------------------------------------------------------
  · **最该先确认的**：单音、以及只有一个声部在响的曲子，输出应该与 V37
    【逐位一致】（N=1 时系数恒为 256，斜坡不动）。
  · 起音时的"噗"声应该没有了；连奏、和弦、快速跑动都试一下。
  · 播放谱子的**同时**去点效果开关：开关应该【等谱子发完才生效】，
    而且**不会**再有别的开关跟着一起变。
  · 空闲时点效果开关：应该和以前一样【立刻生效】。
  · ★ 没验到的：实际听感（噗声是否真的消失、多声部起音是否自然）、
    长时间播放的稳定性、蓝牙在强干扰环境下的表现 —— 这些只能上板用耳朵听。
  · 想调就改这几个地方：
      · 斜坡速度：`top.v` 的 `SCALE_STEP`（1 → 2 会快一倍）
      · 抗噪强度：`uart_rx.v` 的采样点（`baud_i/8` 改成 `baud_i/6` 更宽）
      · 操作数超时：`uart_packet_echo.v` 的 `OP_WAIT_MAX`
