1. 改了什么
--------------------------------------------------------------------------------
① 黑键谱线颜色：16'h7800（半亮暗红）-> 16'h07FF（亮青）   [lcd_master.v]
   用户的诉求是"**改亮**"。原来那个 0x7800 是"同一个红色系、亮度减半"（R=15/31），
   黑背景上确实看不清。

   ★★ 走过的弯路（V48.3 自检抓出来的，如实记下）：
     第一版改成 **16'h001F（纯蓝）**，注释里写的理由是
     "换成蓝色 = 满亮度、红蓝对比一眼分得开"。**这句话是错的**：
       纯蓝 (R=0,G=0,B=31) 的感知亮度只有 **0.11**，
       而原来的暗红 0x7800 (R=15) 是 **0.145** ——
       也就是说那一版**比原来还暗**，正好和用户要的"明亮一点"相反。
     人眼对蓝最不敏感（三通道权重 ≈ R 0.30 / G 0.59 / B 0.11），
     **"满量程" ≠ "看着亮"**。
   ★ 现在取 **青色 16'h07FF**（G=63 + B=31）：
       感知亮度 **0.70**，是旧色的 **4.8 倍**，是那一版纯蓝的 6.4 倍。
     · 和这一屏其余的四种颜色**都不撞色**：
         白键亮红 0xF800 / 2 次谐波黄 0xFFE0 / 背景黑 0x0000 / 边框暗灰 0x4208
     · 波形那一屏用的也是青色，但那是**另一个画面**，不会同屏出现。
   ★ 判据已经写进 `check_rtl_contract.py` 第 **[12]** 节：
     新颜色的感知亮度必须 ≥ 0.55，**且必须是旧色 0x7800 的 2 倍以上**
     —— 也就是把"用户的诉求"本身变成判据，而不是只写个"看起来够亮"。

② 新增小号音色（音色 3 档 -> 4 档）   [top.v / uart_packet_echo.v]
   ★ 资源够：`tone_sel` **本来就是 2 位**，4 档刚好装下，**没有新增任何位宽**；
     实测整版只涨 **+52 LUT / +72 FF**（见 §2），远小于事前估的 ~100 LUT。

   · 译码：`tone_sel == 2'd3` -> `trumpet_on`；按钮循环也扩到 4 档
     （`tone_sel == 2'd3` 时回 0）。`trumpet_on` 跨到音频域走 **trp_s1/trp_s2 两级同步**。
   · 谐波：`harm_brass = harm_raw + (S2 >>> 2)`
       = **在"力度那一份 2 次谐波"之上，再垫一份固定的 2 次谐波**。
       为什么这么做：这个设计的"亮度"只有一个旋钮（由力度给），普通音色是
       "力度小就柔和"；而铜管的特点是**吹多轻都一直是亮的**，所以要有个固定
       "铜管底色"，同时摇杆/MIDI 力度**照样还能继续调亮度**。
       ★ 位宽算过：`harm_raw` 最大 ≈ S2×255/512 = 0.498·S2，加 S2/4 后
         合计 **0.748·S2 < S2**；S2 是 22 位有符号、harm_brass 是 23 位
         -> **不会溢出绕回成负的**（这也有判据守着）。
       ★ `harm_sum` 的三目顺序保持"吉他 -> 小号 -> 笛子 -> 原样"，
         `trumpet_on_audio = 0` 时取到的仍是原来的表达式，**逐位不变**。
   · 包络：新增 4 个常数（**一个老常数都没改**）
       `ENV_ATK_DIV_TRP = 6'd4`（起音 ≈2.6ms 的"起振"，0 就成电子音了）
       `ENV_SUS_LV_TRP  = 8'd255`（按住满幅，铜管是稳的，不像拨弦会自己衰）
       `ENV_DEC_DIV_TRP = 16'd280`（衰减同普通）
       `ENV_REL_DIV_TRP = 16'd140`（释音比普通短一半，像"把气断了"）
       `env_*` 四个三目都把**小号那一支写在最后**，判据是 `trumpet_on_audio`。
   · `0xCA` 音色操作数：**越界（>3）一律退化成 0（"普通"）**，
     既不是取模、也不是夹到 3：
         `tone_val <= (rx_data > 8'd3) ? 2'd0 : rx_data[1:0];`
     ★★ 这和 `0xD0`（显示模式）**故意不一样** —— 那条是**夹紧**到 0~4。
       两条命令的越界语义有各自的道理（音色"退化"是为了不让板子突然发出一档
       用户没选过的音色；显示模式"夹紧"是为了别让界面跳档），
       **谁也别向谁看齐**。详见交接文档**坑 48**（这一条是踩出来的：我口头
       告诉安卓子代理"夹紧"，于是 RTL/Python 说 0、Java 说 3，三方两派）。

③ ★★ 修掉 V48.3 构建后冒出来的**唯一 setup 违例**（-0.155ns）   [top.v]
   现象：`SETUP slack = -0.155ns`，`CLKOUT0 -> CLKOUT1`，
        端点 `rec_mask_s1_0_s18/DI[1]`，数据延迟 20.120ns / 要求 20.000ns。
   根因：`rec_mask_s1` 是两级同步器的第一级，它的 D 端原来直接接**纯组合**的
         `sounding_mask_aud`，而 `sounding_mask_aud = key_mask | sustain_latch_aud`，
         `key_mask` 里又含 `midi_keys_aud`（从当前格的指引掩码展开出来的组合逻辑）。
         于是形成一条**跨两个时钟域、四层组合**的长链：
             midi_guide_s1(clk_audio) -> 展开 -> key_mask
               -> sounding_mask_aud -> rec_mask_s1.D(clk_50m_ext)
   ★ 为什么 V48.2 没报：那时这条链还有 +1.03ns 以上余量；本版加了小号音色
     （音频域）和 js_z 流水（50M 域）之后**布局扰动**，瓶颈从 js_z 跳到了这条
     跨域链上 —— 坑 45 附注早就写过"插完流水要重新看三个域的 Fmax，
     因为瓶颈会从一条链跳到另一条链"，这次跳的是一条**跨域**链（Fmax 表看不见它）。
   治法：**插流水**（本项目一直用的办法）——
     新增 `reg [35:0] sounding_mask_gate;` 在 **clk_audio 域**先打一拍，
     `rec_mask_s1` 改成采这个打拍后的值。跨域那段于是变成**寄存器 -> 寄存器**，
     组合逻辑几乎为零；而那条长链的终点变成 clk_audio 自己的寄存器，
     要求时间从 20ns 变成 80ns，余量一下子有几十 ns。
   ★ 代价：门控掩码晚 80ns（一个 clk_audio 周期）。录音事件时标是 ms 级，
     80ns 完全看不见。`sounding_mask_aud` 本身**一个字节没动**，
     音频域内部（包络起音判据、n_voice 计数）用的还是原来那个组合值，
     **声音逐位不变**。
   ★ 结果：违例端点 **1 -> 0**（见 §2），判据写进交接文档坑 47/48 与
     `check_rtl_contract.py`（"跨域打拍寄存器还在"一条，删了就会红）。

④ 修活一套**已经失效很久**的自检脚本   [testfiles/liss_geom_check.py]
   见交接文档**坑 47**（这一条比它修的那点代码值钱）：
   V35.1 把李萨如的 X 系数从 ×140 改成 ×120、Y 从 ×100 改成 ×120，wire 也跟着
   改名 `x140`->`x120` —— 而这个脚本的正则**还写死着 x140/y100**，于是它
   **既没红也没报错，而是崩在后面的 `%d` 格式化上**（`None`），
   在批量回归里躺了好几个版本（崩的退出码看起来像环境问题，容易被当噪音放过）。
   ★ 修法四条一起做：① 按形状抓 `x<数字>`（不写死）；② wire 名字与移位和**互证**；
     ③ 抠不到就 **check 判失败并提前收工**（绝不带着 None 往下算）；
     ④ 新增常驻扫描器 `testfiles/_scan_stale_sim_refs.py`。
   ★ 扫描器本身也做了**变异测试**（放一个引用 x140 的探针进去，必须被抓出来）
     —— "任何检查工具，都要先证明它【能红】，再用它说全绿"。
   ★ 顺手更正两条老文档里的过时数字（以本版实测为准）：
     李萨如实际占 **col 40..279 / row 1..239**（不是 20..299 / 21..220）；
     **等幅输入现在画出来就是正圆**（140:100 那个椭圆时代过去了）；
     row 的理论下端 120+120=240 落到屏外被夹到 239 —— 圆底有个 **1 像素平台**，
     肉眼看不出来（要消掉得动 RTL，本版没动）。

⑤ 跨语言语义对齐 + 归档方式修正
   · 安卓侧：`clampTone` 改名 **`safeTone`**，语义改成"越界 -> 普通(0)"，
     与板子 RTL、电脑版 Python **三方一致**（分歧原因见坑 48）。
     javadoc 里写明"别和 0xD0 看齐"，并加了一条判据钉住这个边界。
   · 安卓侧音色表扩到 4 档（`TONE_NAMES` 4 项 / `TONE_MAX=3` / 界面第 4 个
     RadioButton / strings.xml 加"小号"）。
   · `testfiles/make_version_archive.ps1`：**归档时把 `music_tr_content.html`
     也带上**。因为 **Fmax / TNS / 违例端点数的汇总表只在这个文件里**，
     别的报告只有资源表和引脚表 —— V48.2 归档时没带它，于是"时序全 0"
     这句话事后无法复核；而 V48.3 恰好就在这些数字上翻过车（见 §2 的 ★★）。

     以后判时序必须**同时看三处**：
       ① TNS 汇总表；② `Numbers of ... Violated Endpoints`；
       ③ 路径表里 slack < 0 的条目（以及最差那几条离 0 有多近）。

  ★ 遗留观察项（本版**没有**动，如实记下）：
     最差 setup 现在是 `midi_guide_s1_0_s5/Q -> keys_ok_s1_s0/D`，**+0.581ns**
     （同样是 CLKOUT0->CLKOUT1、同样进两级同步器第一级）。
     它是"跟谱模式：这一格要求的键都按下了吗"那个判据，属于设计上就按异步
     处理的信号（SDC 里本意是要排除的，见下）。
     ★ 如果以后再往音频域/按键掩码那一带加逻辑，**这条是第一个要看的**；
       治法与 ③ 完全一样（照 `sounding_mask_gate` 的样子给 `keys_ok_aud`
       在 clk_audio 域加一拍，1 个寄存器），本版没做是为了"一次只改一处"。

  ★★ 顺带记录一个**没修但值得知道**的事（**music.sdc 是红线，本版没动**）：
     `music.sdc` 里那句
         set_clock_groups -asynchronous -group [get_clocks {clk*}]
     本意是把三个时钟域标成互异步，但**PLL 派生时钟的实际名字是**
         u_pll/u_pll_0/PLLA_inst/CLKOUT0.default_gen_clk
         u_pll/u_pll_0/PLLA_inst/CLKOUT1.default_gen_clk
     —— **不以 `clk` 开头**，所以 `clk*` 只圈到了 `clk_50m` 一个时钟。
     证据：本版报告里仍然能查到 `CLKOUT0 -> CLKOUT1` 的跨域路径被分析
     （4 条在 setup 前 20 里）。也就是说这一句**没有起到它注释里说的作用**，
     跨域同步器输入那类"假违例"一直是靠**碰巧有正余量**在过关的。
     ★ 真正的修法是把这句改成能圈住派生时钟的写法，但那是改 SDC = 红线，
       而且 SDC 里已经记着"派生时钟不能按名字取"的坑，所以**留给用户决定**。
       本版的做法是**在 RTL 侧把跨域链修短**（③），不碰 SDC。

4. ★ 只能上板子看的（用户要验的）
--------------------------------------------------------------------------------
1. **黑键谱线要明显变亮**：进频谱那一屏，黑键（每八度第 2/4/7/9/11 列）
   应当是**亮青色**，白键是亮红色。
   ★ 请特别看"**和背景分不分得开**"——这正是用户提的问题；
     如果觉得青色太扎眼，可选项（只改 lcd_master.v 里那一个常数）：
     白 0xFFFF / 品红 0xF81F / 橙 0xFD20 / 更亮的红 0xC800。
2. **小号音色**：按板上按钮 7 循环 4 档（普通 -> 笛子 -> 吉他 -> 小号 -> 普通），
   或在上位机那排「音色」点"小号"。听感应当是：
     · **不管力度多轻都一直是亮的**（有一层固定的 2 次谐波垫底）；
     · 推摇杆 Y（力度）**照样还能调亮度**；
     · 按住是**稳的**（不像拨弦自己衰下去），松手收得比普通干脆。
   ★ 同时听另外三档**有没有变**（应当一个音都没变）。

· 最差 setup `midi_guide_s1 -> keys_ok_s1` **+0.581ns**（跨域、同步器输入）：
  本版未动，理由与治法见 §2 的"遗留观察项"。
