0. 一句话
--------------------------------------------------------------------------------
用户原话：

  「LCD 不会卡死了，但是**延音时谱线会被刷掉**，即延音没办法保持谱线，
    **这个看门狗把延音状态当卡死给刷掉了**」

用户判断的方向完全正确 —— 就是 V47.2 加的 LCD 看门狗在**误触发**，
而且误触发之后**画面还回不来**。两条根因、两处修改，见 §1。

--------------------------------------------------------------------------------
1. 改了什么
--------------------------------------------------------------------------------
① **看门狗判据：把"谱线在空转"也算成活着**   [lcd_master.v]
   根因：频谱这一屏是 `S_BAR_WIN <-> S_BAR_DATA` 自循环，而"这一列要不要重画"
   由 `bar_dirty` 决定。
     · 有列脏（高度在变）→ 每画完一列都在两个状态间跳 → 看门狗计数器一直被清；
     · **没有列脏（高度恒定）→ `S_BAR_WIN` 的 phase0 只做
       「`play_idx` 自增 + `phase <= 0`」，`state` 一个时钟都不变** →
       静态画面超过 0.8s 就被误判成卡死。
   ★ "延音"正是"高度恒定不变"的典型场景，所以用户只在延音时看见它。
   ★★ 逐拍算过（`sim_lcd_watchdog.py`）：每列 3 拍 = 6 时钟，一圈 60 列 = 360 时钟
      = **7.2 µs** → **每 111,112 圈、正好 0.800s** 就攒满阈值。
      也就是说：**静态画面每 0.8 秒就被整台重来一次**（`S_POWER_ON` → `S_INIT` → 全屏清）。
   修法：
   ```verilog
   if ((state != lcd_state_d) || (play_idx[5:0] != lcd_play_d))
       lcd_wd_cnt <= 26'd0;      // state 动了【或】谱线列号动了 -> 都算活着
   ```
   ★ 空转一圈 7.2µs，列号必然一直在动，计数器再也攒不到 0.8s；
     **真卡死时 `play_idx` 是冻住的，照样触发** —— 看门狗的本职没丢
     （判据里验了："真卡死仍在 0.800s 触发"、"差一拍不触发"）。

② **看门狗触发时要作废谱线缓存**（否则清完屏一列都不重画）   [lcd_master.v]
   根因：误判/真触发之后走 S_POWER_ON → S_INIT → **全屏清一遍**，
   但 `bar_state[]` 里存的还是清屏前的高度、**和当前目标高度一模一样** →
   `bar_dirty` 恒 0 → **一列都不重画** → 屏幕空在那里。
   ★ 这和 V48 那个"切模式后频谱空白"是**同一个不变量**，V48 补过三个作废点，
     **这是第 4 个场景**（凡是"清了屏/重开一屏"的地方都得作废）。
   ★★★ **但不能照抄"再写一遍哨兵"** —— 这是本版新踩的一个坑：
     照抄那三处的 `for (dm_i...) bar_state[dm_i] <= 9'h1FF;`，实测
     **Logic 从 46941 涨到 47988（+1047，79% → 81%）**；翻综合报告，涨的
     **全在 `u_lcd`**：`Lut 3000 → 4023（+1023）`，其它模块一个数没变。
     原因：`bar_state` 是 **60 列 × 9 位 = 540 位**的数组，
     **再给它加一个写入源 = 每一位都多一级选择**（6 选 1 变 7 选 1）。
   【正解】把"作废"这一位**从 9 位高度里拆出来单独放**：
   ```verilog
   reg [59:0] bar_bad;                       // 每列一位
   wire bar_dirty = bar_bad[play_idx[5:0]] || (bar_state[play_idx[5:0]] != tgt_q);
   // 置位：看门狗分支      bar_bad <= {60{1'b1}};
   // 清除：画完那一列的就地  bar_bad[play_idx[5:0]] <= 1'b0;
   ```
   代价 **约 60 个 LUT**（`u_lcd` Lut 3000 → 3086），**比照抄省了约 937 个 LUT**，
   语义完全一样（**逐列自消耗，不需要任何窗口/计时器**）。
   ★★ 它不是 V48 否掉的 `bar_force` 那种写法：`bar_force` 是**一个**标志位 +
     **一个计时器**清它（"窗口要多长"正是当初翻车的地方）；`bar_bad` 是
     **每列一位**、由画完那一列的同一条语句清掉。判据里专门钉住这两条。

③ **按键判据 `keys_ok` 也跨域打一拍**（清掉最后一条 setup 违例）   [top.v]
   V48.3 归档时，全工程最差 setup 是 `midi_guide_s1 -> keys_ok_s1`，还有
   **+0.581ns**，版本说明里写明"**以后再往音频域/按键掩码那一带加逻辑，
   这条是第一个要看的**"。V48.4 只加了 LCD 域的 `bar_bad`，布局一扰动，
   它果然翻成 **-0.771ns**（全工程唯一 setup 违例，CLKOUT0 → CLKOUT1）。
   修法与 V48.3 的 `sounding_mask_gate` 完全一样：在**音频域先打一拍**，
   让跨域那段变成"寄存器 → 寄存器"：
   ```verilog
   reg keys_ok_gate;
   always @(posedge clk_audio or negedge rst_n)
       keys_ok_gate <= keys_ok_aud;     // keys_ok_aud 本身一个字节没动
   ...
   keys_ok_s1 <= keys_ok_gate;          // 原来是 <= keys_ok_aud
   ```
   ★ 代价：跟谱判据晚 80ns（"人按下键没有按对"是几十 ms 尺度的事，无感）。
   ★ 结果：最差 setup **-0.771 → +2.369ns**。

④ 上位机/安卓：**本次没有协议改动**，两边都不需要改。
   但顺手把**安卓 APK 补出来了**（Gradle 坏，一直没打过）—— 见 §4。

【怎么编的】Gradle 坏（`native-platform.dll` 只有 312 字节），所以新增
  **`build_apk_offline.ps1`**：aapt2 compile/link → javac → 生成库 R 类 → 校验 →
  d8 → 打包 → zipalign → apksigner → 校验，一共 8 步，全都只用 build-tools 里现成的工具。

【★★ 离线打包最大的地雷：库的 R 类】
  · `androidx` 的 `classes.jar` 里**一个 R 类都没有**（AGP 打包时会剥掉；
    实测 `appcompat-1.6.1-runtime.jar` 里 `androidx/appcompat/R*` 条目数 = **0**），
    而库代码运行时要读自己的 R（那些字段在库里是**非 final** 的）。
  · 所以必须自己补一份。★ **不能直接复用上次 Gradle 留下的那份 `androidx_R.jar`**：
    逐条对拍发现 **整个 `id/` 表偏移了 1 位**（因为后来给布局加过一个
    `@+id/rbToneTrumpet`）—— 直接用会让库代码**加载到错的资源**（找 `id/center`
    拿到的是 `centerCrop`），**编译期完全看不出来，只在手机上错乱或崩溃**。
  · 于是写了 `tools/gen_lib_R.py`：把旧 jar **只当"符号清单"**（类名/字段名稳定），
    **值一律按当前资源表重新解析**；`styleable` 例外（它是 `int[] 数组 + 下标`，
    数组元素是 **attr 的 id**，实测 **attr 1154 条全部未移位**，所以那 19 个类原样拷贝）。
  · 再用 `tools/_check_gen_R.py` **把生成的 R 类真加载进 JVM 反射读**
    （`javap` 看不到 `int[]` 的内容），逐条对拍：
    **12729 个 int + 329 个数组，零不一致、零野 id、零下标越界**。
  · 出包后又验了：`apksigner verify` 通过、`aapt2 dump badging` 包名/标签/版本正确、
    d8 **"Missing class" 告警 0**、dex 里能查到
    `safeTone / clampDisp / packToneSet / fxWaitTone` 等方法
    与「小号」「李萨如·相位」「李萨如·干湿」等新串
    （**`clampTone` 不在** —— 证明跨语言对齐那次改动也进包了）。

【踩到的两个工具坑（都记进交接文档了）】
  · **`.ps1` 里不能有中文**：Windows PowerShell 5.1 按 ANSI 读脚本，
    中文字符串会把解析器搞崩（`build_apk_offline.ps1` 第一版就栽在这）。
  · **编辑过的 `.ps1` 会丢掉 UTF-8 BOM**，丢了之后 PowerShell 按 GBK 读，
    中文注释里某个字节会把后面的 `"` 或 `{` 吃掉 → "Missing closing '}'"。
    `make_version_archive.ps1` 就这么坏过一次（已补回 BOM）。
    ★ 编辑 `.ps1` 之后**必须确认前三字节是 `EF BB BF`**。

5. ★ 只能上板子看的（用户要验的）
--------------------------------------------------------------------------------
1. **延音时谱线要能保持住**（本版主修）：
   按住几个音 → 按**延音锁存**（按钮 2）→ 松手，让声音持续十几秒。
   · 谱线应当**一直保持在那个高度**，不再被"刷掉"；
   · 顺手看屏幕**有没有每 0.8 秒闪一下**（那是旧的误触发整台重来）——
     现在不应该再有了。
   · 静音时（不弹）也应当**不闪**（旧版同样在误触发，只是画面变化看不出来）。
2. **LCD 卡死仍要能自愈**（V47.2 的能力不能丢）：
   连续快速按多个琴键，看会不会定住；定住后**等 0.8 秒**应当自己恢复。
3. **跟谱模式仍要正常**（本版给它的判据打了 80ns 的拍）：
   开跟谱、按对键 → 应当照旧往下走；按错 → 应当不往下走。
4. 前几版那几条仍要复验：黑键变亮 / 小号音色 / 5 档显示 / 双向同步 /
   连发谱子不再自己亮混响合唱。
