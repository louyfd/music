V36 —— 真正的双声道输出（中/侧分解 + 可选 Haas）+ 李萨如加"左×右"档
========================================================================

一、这一版做了什么
------------------------------------------------------------------------
两件事，一件是主体（保守地做），一件是顺带（小）：

  A. 【立体声】板子上 DAC 的两路输出都接了喇叭，但 I2S 帧的两个 32 位槽
     原先装的是同一个 mono 样本（等于白接了第二路）。这一版在【输出级】
     做了中/侧（mid/side）分解，左槽装 L、右槽装 R。
  B. 【李萨如加一档】按键 3 的显示循环从 4 档扩成 5 档，在第二位插进
     "左×右"，用来肉眼检查两个声道到底分开了没有。

★ 合成链路（36 声部 / 包络 / 滑音 / 谐波 / 音色 / KS 吉他 / 颤音 / 延迟 /
  混响 / 合唱）【一个字没动】；录音回传、蓝牙协议（0xC0~0xCC）、按键映射、
  ENV_* / GLIDE_STEP / sine_rom / PLL / music.cst / music.sdc / I2S 帧参数
  （I2S_SPEC / FRAME_BITS / BCLK_HALF）也一个都没碰。

二、中/侧分解具体怎么取的（重点）
------------------------------------------------------------------------
mid  = sample_vol —— 就是原来那个单声道最终输出，原封不动。

side = 干声项 + 湿声项，全部只取【已经算出来的】信号：

    合唱：(dry_sample - s_cho) >>> 2      ← 合唱关掉时 s_cho ≡ dry_sample，
                                            这一项逐位为 0
    延迟：-(dly_wet  >>> 3)               ← 延迟关掉时被门控成 0
    混响：-(rvb_wet  >>> 3)               ← 混响关掉时被门控成 0

     L = mid + side
     R = mid - side        （Haas 开时右路的 side 换成延迟 732 点的那一份）

  为什么用 (dry_sample - s_cho) 而不是"合唱湿声 tap"：
    · 合唱关掉时它【天然为 0】，不需要额外的门控位 ——
      "全效果关掉 = 逐位退化成 mono"这条硬约束是白送的；
    · cho_mix = (dry + wet)/2（干湿各半），所以
          side = (dry - wet)/8
          L = 0.625·dry + 0.375·wet
          R = 0.375·dry + 0.625·wet
      系数全正、和为 1（凸组合）→ 峰值不会超过 max(|dry|,|wet|)，
      也就是【不比现在的 mono 响、也不会凭空多出削顶】。

  左右微调（"干声略偏左、混响/延迟略偏右"）：只体现在 side 的符号上 ——
  干声取 +、湿声取 −，于是 L 里干声多、湿声少，R 里反过来。零额外电路。
  ★ 干声本身没法再做独立增益倾斜：只要 side 里带上"一直非零"的干声分量，
    全效果关掉时 side 就不为 0、L/R 立刻不再相等，直接违反硬约束。所以
    倾斜只能这样"干 vs 湿相对着分"。

★ 为什么没有新增 RAM 读口：
  本工程的教训是"给已有存储器多开一个读口，综合器就不肯再把它推断成
  BSRAM"。所以 side 一律复用已经读出来的那几个抽头（cho_* 插值结果 /
  dly_tap / rvb_t*），一个都没多读。自检脚本会把 cho_ma / cho_mb /
  dly_mem / rvb_m1~m3 的引用次数和改之前逐个数一遍，必须完全一样。
  本版唯一的新存储器是 Haas 那条【新的】1024×16 RAM（单写口 + 单读口，
  标准推断写法），占 1 块 BSRAM —— 不是给旧存储器加端口。

三、Haas（可选，默认开）
------------------------------------------------------------------------
  · 长度：732 点。SR = 12.5MHz/256 = 48828Hz → 14.99ms ≈ 15ms。
  · 存储：1024×16 = 1 块 BSRAM（单写单读）。
  · 开关：localparam HAAS_ON（默认 1），关掉整块 RAM 会被综合器裁掉。
  · ★ 只延迟【side】，不延迟整条 R。整条 R 被延迟的话 side=0 那一档
    L 和 R 就不再逐位相同（R 会比 L 晚），直接违反硬约束。
  · ★ 代价写在明处：Haas 开着时 L + R = 2·mid + (side − side_d)，
    多出一份"干湿两份 side 之差"的残差。这是【任何】通道间延时都躲不掉的
    （左右不同时刻，和就一定不等于 2×mid）；但 mid 在 L/R 里都没有被延时，
    所以单声道兼容性不受影响。HAAS_ON=0 或 side=0 时 L+R = 2×mid 严格成立。
  · 上电填充期（fx_ready 之前）BSRAM 内容未知，这段期间直接用本拍的 side，
    和延迟/混响那两条线的处理一致，不会"啪"一下。

四、I2S 第二槽怎么接的
------------------------------------------------------------------------
  只改【数据源】，不动帧结构：
      i2s_load   左槽 = {st_l[15:0], 16'b0}     （原来是 sample_vol）
      i2s_load_r 右槽 = {st_r[15:0], 16'b0}     （原来是同一个 sample_vol）
  右声道起始分支（i2s_bit_cnt == I2S_HALF_IDX）里装载 i2s_load_r，
  其余（一个 BCK 的 dummy、33 位移位寄存器、MSB-first、左对齐）一模一样。
  STEREO_ON=0 时 i2s_load_r 就是 i2s_load 本身，两个槽逐位同源。
  ★ 装载值【故意不打拍】：打了拍 DAC 会比原来的 mono 版晚一个采样点
    （20.5µs），数值序列一样但"逐位回到原样"就不再严格。音频域是
    12.5MHz（80ns/拍），这几个 21 位加法 + 限幅的余量充足。

五、五档循环的档位编码
------------------------------------------------------------------------
  disp_mode（3 位）          0=频谱  1=波形  2=左×右  3=干声×效果后  4=相位
  wave_mode（给 lcd_master）  = (disp_mode == 1)
  liss_on                    = (disp_mode >= 2)
  liss_src（2 位）            = disp_mode - 2  →  0=左×右 1=干声×效果后 2=相位
  回绕判据 >= 3'd4，lcd_master 里 liss_src 也扩成 2 位、两级同步后做 3 选 1。
  映射 / 打点 / 余辉 / 边框 / 十字【全部复用】，X/Y 刻度仍然是 ×120。
  L / R 两个样本和 wave_send 在【同一个音频沿、同一个 always 块】锁存
  并共用同一个 wave_tgl 翻沿，所以取到的天生是同一采样点的 (X,Y)。

  ★★ 单声道内容在这一档会画成一条【对角线】—— 那是【正确】的 ★★
     对角线 = L 和 R 逐位相同 = 此刻确实没有立体声信息（mono 内容本来
     左右就一样）。效果全关时看到它就是对的，不是 bug；
     开合唱/延迟/混响后图形会张开成环/螺旋/花。

八、上板子看什么 / 没验到的
------------------------------------------------------------------------
  · 按键 3 按到第 2 档（李萨如·左×右）：弹单音，效果全关时是**一条对角线**
    （正确）；开合唱/延迟/混响后应该张开成环/螺旋/花。
  · 打开合唱（按钮 9）后左右喇叭应该有区别：干声偏左、湿声偏右，R 还多
    15ms 的 Haas 延迟，声场应该比原来宽。
  · ★ 没验到的：实际声场宽度、左右分离度、Haas 15ms 好不好听、
    "会不会觉得人声偏左/偏右" —— 这些只能上板子用耳朵听。
    能调的旋钮：STEREO_ON / HAAS_ON / HAAS_TAP / ST_CHO_SHIFT（越大分离
    越小）/ ST_WET_SHIFT，都在 top.v 输出级那一段，改完重跑一次综合即可。
  · ★ 上电那 42ms（fx_ready 之前）Haas 抽头不用，声场是"窄"的，
    属于正常现象。
