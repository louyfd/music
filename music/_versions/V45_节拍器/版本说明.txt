1. 本次新功能：节拍器
--------------------------------------------------------
用户要求：
    · 把板载 READY 灯（引脚 U12）当作节拍器
    · 默认 4/4，速度默认 100 BPM（范围 30~240）
    · 通过蓝牙（SPP）调节：速度、拍号分子（1~8）、分母（2/4/8）
    · 每拍闪得一样长（不区分强拍弱拍）
    · ★ 【只当作外部参考，不参与任何其它模块】

实现（FPGA 侧）：
    · 灯：原"音色指示"（led_cnt[23:0] + case(tone_sel) 的 led_out）
      【整块删除】，改由节拍器驱动。已 grep 确认这两个信号全文只在那里用。
      极性不变，仍由 LED_ACTIVE_LOW 那一个 assign 处理。
    · 计数器放在【clk_50m 域】：
        - led 这根脚本来就是 clk_50m 驱动的
        - clk_50m_ext（UART/LCD）是余量最紧的域，不去挤它
        - clk_50m 约束 50MHz
    · 参数跨域：工程既有的"翻转沿 + 数据握手"（metro_tgl）。
      参数是准静态的，看到沿时数据早已稳定。
    · 拍点算法：★ 不用除法也不用乘法 ★
        1ms 基准 -> 每 1ms 往 acc 里加 BPM，加到 >= 60000 就出一拍，
        同时减掉 60000（余数留在 acc 里）。
        一拍 = 60000/BPM 毫秒，【平均】周期精确；
        除不尽的 BPM 会在相邻两拍之间一长一短地自动补偿。
        取值范围：acc 恒 < 60000，BPM <= 240 -> acc+BPM < 60240，16 位够。
        BPM=0（关）时 acc 按住归零 —— 免得重新打开时抢一拍。
    · 每拍亮 80ms（常数在 mt_flash <= 8'd80 那一行，想改改这里）。
    · 小节内拍号 0 起算，只用于状态回报，不参与闪烁。

实现（协议侧）：
    · 上位机 -> FPGA：0xCF + 3 字节  BPM / 分子 / 分母编码
        分母编码 0->2 分，1->4 分，2->8 分
        夹紧在 FPGA 侧做：BPM 0=关、1~29->30、>240->240；分子 1~8；编码 0~2
    · FPGA -> 上位机：0x5E + 4 字节  BPM / 分子 / 分母编码 / 当前第几拍
        ★ 全新的独立帧，【0x5D 一个字节都没动】
        只在设置变化时发；另外复位后和收到 0xCB 时各强制发一次
        ★ 所以上位机连上后发一次 0xCB，就能顺带拿到节拍器状态
          （PC/安卓侧目前还没用上这一点，可以后续加）
    · 0xCF 已登记进操作数长度表（PC 的 _OP_LEN / 安卓的 opLen），长度 3
