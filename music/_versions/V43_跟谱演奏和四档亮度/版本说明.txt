V43 —— 跟谱演奏模式 + LED 四档亮度 + 物理顺序映射
========================================================================

一、这一版做了什么
------------------------------------------------------------------------
1. **跟谱演奏模式**（新增命令 0xCE）
   打开之后：当前时间格要求的键【全部按住】才前进到下一格。
     · 必须【松开再按】才算下一格（用上升沿，不用电平）——
       否则按住不放会自己一格一格往下走，同音重复处尤其明显
     · 休止格自动通过
     · ★ 不卡死：wait_mode 是电平状态，0xCE 和 TTP 按键13 随时能翻回 0，
       一翻回就立刻继续播 —— "开关自动恢复"而不是"门控永久失灵"（坑 20/22）
     · ★ 正常模式零影响：wait_mode=0 时 slot_go 恒 1 → can_load 恒 1
       → 播放器行为与 V42 逐位相同
   开法：上位机「跟谱」按钮（电脑版 + 安卓版）或 TTP 按键13，两端同步。

2. **LED 四档亮度**（用户定的档位）
     90% (0xE6) = 现在要弹 + 下一格也要弹
     75% (0xBF) = 现在要弹
     30% (0x4D) = 下一格要弹（提前预告）
     70% (0xB3) = 手弹按下的键（不播放时按琴键点亮，保留）
   ★ 优先级就是上表顺序，手弹放最后 —— 谱子要求的键保持自己的档位，
     不然一按对灯反而从 90% 掉到 70%。

3. **LED 物理顺序映射**（用户实测给的对应关系）
   物理第 1..12 个键 -> 键号 05 00 06 01 07 08 02 09 03 0A 04 0B，后两八度各 +12/+24
   ★ 只改"哪颗灯显示哪个键"，与发声、与键位映射【完全无关】。

三、★★★ 本版最值钱的两条教训 ★★★
------------------------------------------------------------------------
【教训 1】数组的读地址前面串了加法器，它就会掉出 BSRAM
    V41 时 --SSRAM(RAM16) = 214 块；V43.5 变成 817 块，BSRAM 从 88 掉到 86。
    原因：F 方案把 slot_mask 的读地址从 rd_slot 改成 rd_next（= rd_slot + 1，
    一个加法器输出）—— 地址前面串了加法器，综合器就不肯推断 BSRAM，
    36×1024 变成 594 块分布式 RAM。
    ★ 这正是本文件第 1027 行注释警告过的事（"选择器正好串在 BSRAM 地址前面"）。
      我一边引用那条注释、一边自己踩了进去。
    ★ 而"影子数组试了 5 种写法都进不了 BSRAM"那次，其实方向也是错的 ——
      真正的变量是【读地址】不是【写语句】。

【教训 2】★★ 对比资源必须 PnR 对 PnR，不能拿综合比 PnR ★★
    我曾经拿 V41 的 PnR 数字（Logic 38687 / RAM16 214）去比 V43 的
    【综合】数字（43794 / 817），得出"影子数组值 4600 个 LUT"的结论 ——
    ★ 这个结论是错的，而且我在这个错前提上连续推理了好几轮，
      浪费了 5 次构建/综合。
    ★ 正确做法：syn_only.tcl 只看"数组有没有进 BSRAM"，
      最终 LUT 数与时序【只能看 impl\pnr\music.rpt.txt 和 music_tr_content.html】。

四、走错的弯路（留着，避免以后重走）
------------------------------------------------------------------------
  影子数组（给"下一格"用）一共试了 5 种写法，全部没进 BSRAM：
     1. if (wr_slots != 0) slot_nxt[wr_slots-1] <= pend_mask;   地址是组合线
     2. 去掉条件门，地址仍是组合线 wr_nxt
     3. 使能/地址/数据全打进寄存器，写在独立 always 块
     4. 读口改成寄存器直读（还让 Tech-Mapping 卡住 7 分钟，坑 13 现象）
     5. 地址用寄存器 wr_m1 + 写在同一个块（形状与 slot_oct0 一致）
  → 结论：这条路放弃。最后改用 **F 方案**：读早一格
        wire slot_ahead = slot_mask[rd_next];
        if (load_now) slot_cur_r <= slot_ahead;
    一块新存储都不要，而且【发声路径的相位一点没变】
    （装载那一拍 rd_slot 还是旧值 → rd_next 正好是新格 → 下一拍生效，
      和原来 slot_mask[rd_slot] 同一拍生效）。
    ★ 掩码和八度【必须一起换、级数一样】，绝不能出现"新掩码配旧八度"（坑 2）。

六、协议（同步改了文档 tools\协议说明_v2_和弦扩展.md 第 14 章）
------------------------------------------------------------------------
  【上位机 -> 板子】0xCE + 1 字节：0x00 = 正常播放（默认），非 0 = 跟谱演奏
      ★ 和 0xC9/0xCA/0xCB 同类：不受开窗限制、随时可用、可插队
      ★ 操作数必须登记进操作数长度表（否则分块会把命令和操作数切开，坑 21）
  【板子 -> 上位机】0x5D 状态帧从 3 字节扩成 4 字节，第 4 个 = 跟谱模式 0/1
      ★ 上位机解析要兼容三种固件：音色字节 <= 2 才算、模式字节 <= 1 才算，
        认不出就【不吃掉】它 —— 这样对着老固件的 3/2 字节帧也不会错位
      ★★ 上位机两端必须同步更新（电脑版 + 安卓版）
