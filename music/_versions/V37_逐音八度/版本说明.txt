V37 —— 逐音八度：同一格和弦里每个音各有各的八度（V32 那个洞补上了）
====================================================================

一、这一版做了什么
------------------------------------------------------------------------
一句话：**让"同一格里跨好几个八度"的和弦也能按原音高发出来**。

V32 给了一格一个 0xCC 八度偏移，"高两个八度的那句旋律"于是能按原调弹。
但那个偏移是【一整格共用一个】的，所以：

    左手 C2 + 右手 C6（跨 4 个八度）同时按下
    -> 一整格只能挑一个八度，怎么挑都有一个音超出 36 键音域
    -> 多出来的那个只能【折返】(fpga_midi._fold_into_board)，音名对、八度错
    -> 旋律线就断了

这一版把八度从"逐格"细化到"逐音"：同一格里每个音走【自己的键 + 自己的八度】，
C2 和 C6 各发各的，**零折返**。

★ 合成链路（36 声部 / 包络 / 滑音 / 谐波 / 音色 / KS 吉他 / 颤音 / 延迟 /
  混响 / 合唱 / 立体声输出）【一个字没动】；PLL / music.cst / music.sdc /
  I2S 帧参数 / ENV_* / GLIDE_STEP / sine_rom 也一个都没碰。

二、关键认识：缺的不是振荡器，是"每个音自己的八度"（重点）
------------------------------------------------------------------------
最先想到的方案是"再加 36 路振荡器"。查了资源账之后否掉了，原因是：

  · 36 路振荡器的 sine_rom **一块 BSRAM 都不占**（综合日志里 sine_q 只被
    提取 1 次，落成了 LUT：128 LUT + 16 REG 每份）。所以"加振荡器"本身
    不撞 BSRAM，但也不解决八度粒度问题；
  · 真正的硬墙是 **KS 吉他的 36 条弦**：`gen_ks[N].u_ks` 每条占 1 块
    BSRAM，合计 36 块 —— 新增一组若要配 KS 弦，82+36 = 118 直接顶满；
  · 而 top.v 里 `voice_oct[]` **本来就是逐声部存的**（V32 为了"释音尾巴
    不被一起搬八度"就已经做成 36×3 位）。缺的只是把逐键八度【从协议送进来】。

所以这一版**一个振荡器都没加**，只加了一条"逐键八度"的通路：

    板子上实际发出来的音高 = key_to_midi(键) + 12 × 这个键的八度
    36 键 = 3 个完整八度 + 八度可取 -4..+3
    -> 任何音高都能找到某个键【精确】发出它

三、协议：和弦内逐音八度前缀 0xCD
------------------------------------------------------------------------
新增一个字节（0xC0~0xCC 的既有语义一个都没改）：

    0xC0 [0xCD <oct>] <音号> [0xCD <oct>] <音号> ... 0xC1

  · 0xCD **只作用于紧跟其后的那一个音号**，语义与 0xCC 完全一致
    （0..3 = +0..+3；4..7 = -4..-1，两补数）。
  · 没有 0xCD 的音号继续用本事件的 oct（整格八度）。
  · **一个 0xCD 都不发的帧逐字节不变** —— 老上位机、老谱子、老测试全部照旧。
  · 0xCD 不会和音号撞车：音号最大 0x23，0xCD 在命令区且此前未分配。
  · 它和 0xC2/0xC6/0xC9/0xCC 一样是【原始数据】，RTL 用 key_oct_left
    计数器挡着 —— 否则一个 0x01 之类的八度值会被音号分支当成"第 1 号键"点亮。

协议文档已同步：tools\协议说明_v2_和弦扩展.md 第 13 章。

四、板内怎么实现的
------------------------------------------------------------------------
uart_packet_echo.v：
  · `KEY_OCT_BYTE = 8'hCD`；`key_oct_left` / `key_oct_seen` / `key_oct_pend`
  · 和弦累积 `acc_oct_b0/b1/b2`（三个 36 位向量，各存八度的一位）
    + `acc_oct_set`（36 位：哪些键被 0xCD 显式指定过）
  · **落盘时烘平**（全文件唯一写 slot_oct 的地方）：
        slot_oct[wr_slots][g] = acc_oct_set[g] ? acc_oct[g] : pend_oct
    没被指定过的键一律填整格八度 —— 这就是"老谱子逐位不变"的来源
  · 新存储 `slot_oct0/1/2`（三个 36 位 × 1024 数组 = 6 块 BSRAM）
  · `midi_octs`（108 位）与 `midi_keys` **同一拍、同一个 always 块、
    同一个 gate** 输出 —— 掩码和它的八度天生配对

top.v：
  · `midi_octs_s1/s2` 两级同步（级数与 midi_keys 的"当前格" midi_keys_s2
    对齐，score_new 用的就是它）
  · 起音：`voice_oct[gt] <= midi_octs_s2[gt*3 +: 3]`（原来是 oct_s2）
  · 滑音判据：
        wire [2:0] oct_new_g = score_new[g] ? midi_octs_s2[g*3 +: 3] : oct_s2;
    乐谱起音用【本键自己的】新八度；手弹/其它来源仍用 oct_s2（与 V36 逐位相同）。
    ★ 这一条不能省：拿整格八度去比，跨八度大跳时会从【另一个八度】滑上来 ——
      那正是 V33 修过的"大跳时音头跑到别的八度"换个形式复现。

五、上位机：逐音分配 (键, 八度)
------------------------------------------------------------------------
fpga_midi.py 的 `assign_keys()`（安卓版 FpgaMidi.assignKeys() 逐条对应）：

  · 候选：对 o ∈ {0,1,-1,2,-2,3,-3,4,-4}，只要 m-12o ∈ 45..80 就是一个候选
  · 约束：**键互不相同**（一个声部同时只能发一个音）
  · 求解：二分图匹配（Kuhn 增广路）。n <= 36、每个音 <= 3 个候选，代价可忽略，
    而且**只要存在"不撞键"的方案就一定找得到**
  · 偏好顺序（越靠前越优先）：
      ① 与上一格同一个音高用同一个 (键, 八度)   <- 稳定优先
      ② 避开上一格还在响的键
      ③ |八度| 小  ④ 优先原调 ⑤ 键号小（保证确定性）
    ★ ① 排在 ② 前面是 V33 用听感换来的教训：同一个音高在两格之间【换了键】，
      前一个音的余音会被后按下的那个音掐掉（听感是"截断"）。

★ 物理上限（写在这里免得以后当成 bug）：36 个键只覆盖 3 个八度，所以**任何
  音名最多只有 3 个键**能精确到达它。同时响 4 个以上同音名的音（C2/C3/C4/C5/C6）
  时匹配必然不够 —— 这时多出来的音会折返到还空着的键，**保证一个音都不丢**，
  并记进报告的 folded。这是物理约束，不是缺陷。

六、构建结果
------------------------------------------------------------------------
资源（基线 V36：Logic 36,904 / Register 13,342 / BSRAM 82 / DSP 55.5）：

    Logic      37463/59904   63%   （+559）
    Register   13667/60780   23%   （+325）
    BSRAM         88/118     75%   （+6，正是三个 slot_oct 数组）
    DSP         55.5/118     48%   （+0 —— 一个乘法器都没多）
    --SDPB 81 / --SDPX9B 6 / --pROMX9 1

  ★ 综合阶段的分模块资源（impl\gwsynthesis\music_syn_resource.html）：
    u_uart_packet_echo 的 BSRAM 从 2 涨到 8（+6），其余模块 BSRAM 一块没变。

时序：impl\pnr\music_tr_content.html 的 Total Negative Slack Summary
    clk_50m    Setup 0.000 / 0 ｜ Hold 0.000 / 0
    CLKOUT0    Setup 0.000 / 0 ｜ Hold 0.000 / 0   ← 音频域，0 条负 slack ✔
    CLKOUT1    Setup 0.000 / 0 ｜ Hold 0.000 / 0
  ★ 三个时钟域全部 0 条负 slack（V36 时 CLKOUT1 上还有一条 u_lcd 的临界路径，
    这一版连它都没有了）。

产物：impl\pnr\music.fs（20.2MB）+ music.bin（2.5MB）

★ **这一版构建明显变慢：16.2 分钟（V36 是 7~8 分钟）**。
  慢在【综合的 Tech-Mapping Phase 2 -> 3】这一级，实测约 7 分钟（V36 是秒级）。
  已排除的原因：宽向量动态位选（acc_oct[idx*3 +: 3]）已经改成三个 36 位向量的
  位选写 + 三个 36 位数组，仍然慢；把输出重定向到文件（不经管道）也一样慢。
  结论是**综合器对新增的这几块存储器/跨模块 108 位总线的映射做得极重**，
  但**功能与资源/时序都没问题**。留给下一版优化（见第九节）。
  日常迭代可以用 testfiles\syn_only.tcl 只跑综合，省掉 PnR 的时间。

八、上板子看什么 / 没验到的
------------------------------------------------------------------------
  · 用电脑版放一首【同格跨音区】的谱子（比如低音 C2 与高音 C6 同时按的和弦）：
    V36 会有一个音折八度，这一版两个音都应该在【原本的八度】上。
    报告里会写 "★ 逐音八度 : N 格用了"。
  · **音域内的谱子应该和 V36 听起来一模一样**（一个 0xCD 都不发，
    逐字节相同）—— 这是最该先确认的一条。
  · ★ 没验到的：实际听感（跨音区大跳是否真的更连）、左手低音 + 右手高音
    同时按时的声部避让效果、极端和弦（同音名 4 个以上八度）的退化听感。
    这些只能上板子用耳朵听。

  ★ 想调就改这几个地方：
    · 可用的八度档位 / 优先级：fpga_midi.py 的 `_OCT_STEPS` 与 `assign_keys()`
      里 `_rank()` 的排序（安卓版在 FpgaMidi.OCT_STEPS / rankOf）
    · 报告文字：`MidiReport.text()`（安卓版 Report.text()）
    · 逐键八度的存储宽度：uart_packet_echo.v 的 slot_oct0/1/2
