V31 —— 效果开关 / 音色也能在上位机上切（两端同步）
========================================================================

这一版做了什么
------------------------------------------------------------------------
板子上那 8 个效果（滑音 / 延音锁存 / 音色(谐波) / 颤音 / 延迟 / 笛子 / 混响 / 合唱）
原来【只能用 TTP 触摸按钮切】，上位机里看不到也改不了。这一版让两端都能切：

  · 上位机（蓝牙串口助手，电脑 + 安卓）里多了一排效果开关 + 一个三档音色选择
  · 板上的 TTP 按钮【继续保留】，谁改了都会通过 0x5D 状态帧告诉对方 —— 两边始终一致
  · 连上以后上位机自动发一条 0xCB 问一次状态，界面立刻和板子对齐

★ 效果开关用的是"翻转第几位"（和按物理按钮同义），不是"设成 1/0"：
  板子才是权威，上位机不需要知道当前状态就能安全地切，
  也就不会出现"软件以为它是关的、其实是开的，一设反而设反了"。

★ 音色是三档（普通 / 笛子 / 吉他），一位翻转表达不了，所以单独一条命令直接选档。
  （0xC9 的位 5 仍然保留"音色循环"语义 = 等价于按板上按钮 7，但界面用的是 0xCA。）

------------------------------------------------------------------------
协议（详见 tools\协议说明_v2_和弦扩展.md 第 12 章）
------------------------------------------------------------------------
上位机 -> 板子（都放在"不受开窗限制"的分支里，随时可发）：

  0xC9 + 位号 0..7      翻转 fx_state 的第 bit 位
                        位号 = bit0 滑音 / bit1 延音 / bit2 音色(谐波) / bit3 颤音 /
                               bit4 延迟 / bit5 笛子(=音色档，等价于按钮7) /
                               bit6 混响 / bit7 合唱
  0xCA + 0/1/2          直接设定音色：0 普通 / 1 笛子 / 2 吉他
  0xCB                  请板子立刻回报一次状态

板子 -> 上位机：

  0x5D + 效果 8 位 [+ 音色 0..2]
      老固件(V29 及以前) = 2 字节；V31 起 = 3 字节
      ★ 改成【只要状态变了就上报】（原来只在录音时上报），两端才能互相同步
      ★ 上位机解析兼容两种：第 3 个字节 <= 2 才算音色吃掉，否则按老固件处理；
        音色字节还可能落在下一个串口批次里，所以解析器要留"等一个字节"的状态

★ 操作数是原始数据（可以是 0xAA/0xFF/0xC0），RTL 里用 fx_left / tone_left
  两个计数器挡着 —— 和 0xC2/0xC6 同一个道理；越界值一律退化成最保守那一档。

------------------------------------------------------------------------

  · ★ fx_req 和 fx_req_set 分成两个寄存器：置位在"收字节"那个 always 块、

  · 新增 tone_sel_in 输入 + 本域两级同步（top.v 那侧是 clk_50m 域）

src\top.v

        btn_xxx  ->  btn_xxx | fxw_xxx

  · 音色：tone_sel 多一条 else if (tonw_we) tone_sel <= tonw_val_s2;（直接选档）

  · ★ 音色档 bit5 在 fx_state 里仍然是 flute_on，一个字节的定义没变，
    所以老上位机看到的还是"笛子开/关"，不会被新固件搞乱

★★ 时序：这一版有 8 条 setup 负 slack，全在 CLKOUT1(clk_50m_ext) 上，
   TNS -7.999ns，最差一条 -1.111ns：
       u_lcd/wave_buf_wave_buf_0_0_s/DO[2]  ->  u_lcd/cur_data_7_s1/D
   ★ 重跑了一遍布局布线，结论一模一样（还是 -7.999 / 8 条），
     所以这个不是"这次运气不好"，是稳定复现的。
   ★ 这条路径是【LCD 波形显示那块 BSRAM 读出来、经过共用的一段组合逻辑
     进 cur_data 寄存器】——cur_data 被好几路显示状态机共用，本身就是一个
     很宽的 mux；wave_buf 又是 BSRAM，读出延迟大，两下一叠加就超了。
     它和这次新加的东西没关系：
       · V30（合并吉他那版）这次是 0 违例，而 music_player1 自己那次构建
         在同一个域上也有 -1.433ns —— 同源不同次布局布线的差别
       · 这条路径在 V26/V27 就有名（当时也是 u_lcd/wave_buf 的路径），
         属于"一直在及格线上晃"的老路径
       · 它只影响 LCD 的显示数据通路；音频在 clk_audio 域，UART 收发的
         路径不在违例名单里，都不受影响
     真要彻底解决：给 wave_buf 的读出加一拍流水（读 RAM -> 寄存器 -> 再用），
     或者把 cur_data 那个宽 mux 拆开。属于 lcd_master 的改动，
     等哪天 LCD 上真看到花屏/斜纹再动 —— 现在动它反而容易碰坏正在工作的显示。

怎么用
------------------------------------------------------------------------
【烧录】_versions\V31_效果开关上位机可控\bitstream\music.fs（要重烧：
        0xC9/0xCA/0xCB 和 3 字节状态帧都是新固件才有的）

【电脑版】发送区「效果开关」那一行：
    · 点某个开关 = 让板子翻转它（按下去会变成深色，代表开着）
    · 音色下拉框选 普通 / 笛子 / 吉他
    · 「刷新状态」= 问板子当前是什么状态（连上时程序会自动问一次）
    · 板子上按 TTP 按钮，软件上这排开关也会跟着动

【安卓版】「演奏」页签最上面那一节，用法一样。

【板子按钮照旧】按钮1 滑音 / 按钮2 延音 / 按钮3 波形(LCD) / 按钮4 音色(谐波) /
    按钮5 颤音 / 按钮6 延迟 / 按钮7 音色循环(普通->笛子->吉他) / 按钮8 混响 /
    按钮9 合唱 / 按钮10 录音开关。上位机改了这些开关，板子上的按钮一样还能用。

------------------------------------------------------------------------
注意 / 已知限制
------------------------------------------------------------------------
· 录音回传里"音色"只有 flute_on 这一位：录吉他那一段，上位机还原出来是
  【普通音色】。要把吉他也录进去得动 0x5D 的语义（现在多出来的那个字节只用于
  实时显示，没有进录音时间轴）。
· 效果指令在【正在发谱子】的时候会排队（可能等好几秒才生效）。
  想立刻生效：先点「停止发送」。
· 老固件 + 新上位机：0x5D 只有 2 个字节，上位机认（音色显示"未知"），
  但 0xC9/0xCA/0xCB 板子不认（静默丢弃）—— 也就是说开关点了没反应。
